更新：2026-10-11。当前包含后台流程与原生新进程启动基线，**不代表全部 UI 性能验收完成**。

## 1. 环境与边界

- Mac16,8，Apple Silicon，24 GiB 内存；macOS 27.0.1（26A434）。
- Swift 6.4 / Xcode 27；Release 优化构建；Apple Git 2.54.0。
- 每项保留 30 个串行样本；中位数使用中间两项平均，P95 使用 nearest rank。
- 文件系统缓存已由 fixture 创建预热。`firstRunMs` 仅是首个测量调用，不能称为操作系统冷缓存。
- Release 应用构建于 04:12:43 完成，fixture 于 04:12:46 就绪，随后开始测量；采样未与该构建重叠。
- 第 3～4 节后台测量包含 Git、解析、显示行/高亮准备和图布局；不包含 SwiftUI 渲染、屏幕滚动或 VoiceOver。原生窗口启动另见第 5 节。

[`create-benchmark-fixtures.py`](../scripts/create-benchmark-fixtures.py) 只创建新目录，拒绝覆盖已有目标；Git 身份、配置与 Hook 均隔离。

| 已跟踪文件 | 1,000 | 100,001 |
| 提交 | 1,000 | 100,000 |

| 改动文件 | 20 | 21 |
| 普通差异源文件 | 80 行 | 80 行 |
| 大型差异源文件 | 无 | 100,000 行，约 11 MiB |

历史使用确定的时间戳、线性提交与 20 个指向旧提交的引用。多分支合并、Octopus 多父提交和浅克隆另由功能测试覆盖；本基线不能替代复杂图的性能场景。

```bash
scripts/benchmark.sh
```

命令会构建 `WeGitBenchmarks`，生成两套 fixture，输出 JSON 原始样本，并保留 fixture 供原生 UI/Instruments 继续测量。输出位于忽略跟踪的 `.build/benchmarks/run-*`。此工具不执行网络操作，不修改用户仓库。

## 5. 原生新进程启动

```bash
scripts/benchmark-ui-launch.sh
```

此命令需要可交互桌面，会反复打开并关闭应用。参数域临时关闭仓库和窗口恢复，不改写这些偏好，不自动打开仓库。测试在原生 XCTest 控制下执行；Xcode 给被测 Release 应用附加测试签名权限，测完后必须用普通 Release 构建重新生成交付包，打包脚本会拒绝残留测试权限。

## 9. 失败回合与缓存修复

行尾与选区源码变化后的普通仓库 30 次回合保留在 `.build/ui-benchmarks/workbench-q2Q1dL/Workbench.xcresult`。外壳 P95 365.96 ms、Status 316.28 ms、Diff 156.35 ms、History 248.48 ms、外部稳定写入到新快照绘制 558.32 ms。Status 和 Diff 未达预算；第 7 节较早的通过结果不能替代这一回合。

随后修复原生文本测量缓存：内容或字体/属性变化清空缓存，缓存键使用有效宽度，并核对实际 TextKit 容器宽度。关闭 widthTracksTextView，由 SwiftUI 测量提案统一设置容器，防止原生 frame 变化悄悄改变换行宽度。背景 Status 使用现有 GitEngine 值副本设置 GIT_OPTIONAL_LOCKS=0，实际索引断言在两套 Git 下通过。性能夹具在 Runner 私有域复制，update-index --refresh 完成后才开始测量；这是明确的热缓存条件。

性能脚本在 XCTest 返回失败时仍导出样本和构建回执，自动生成 workbench.json（源码摘要、硬件、工具链、夹具、逐项中位数/P95/预算和原始样本）。1 次 Smoke 的 passed 为 null，不能当作验收通过。30 次最终源码重测结果继续单独追加，预算保持不变。

## 11. 私有夹具的预热校验修复

在预热前后比较实际索引字节、核对 exit 1 的每行输出和改动文件数后，旧预热立即失败：`.build/ui-benchmarks/` 中由 `/usr/bin/git` 启动的 Runner 回合只得到一行输出，不能当作 20 个已修改文件的 `needs update`。以前单独接受 exit 1 的逻辑没有证明索引修复成功。因此，第 9～10 节的回合保留原始样本和失败结论，其“索引已修复”的条件声明撤回；不能当作最终热条件验收。

脚本现于 Runner 外通过 xcrun --find git 解析当前 Xcode 的实际 Git，传入隔离的测试进程。修复后的预热检查已通过：只有预期的 20/21 条 needs update 可接受 exit 1，且复制后的索引字节必须实际改变。输出作为 XCTAttachment 保留；任何权限、工具链或修复异常都在计时前失败。大型滚动夹具采用同一实际 Git 路径。

性能 Harness 增加仅用于单次诊断的附加前置等待；30 次验收明确禁止该暂停参数。并发的 Git、快照尝试及界面区间分别使用独立 signpost ID，避免独占 ID 使区间重叠。普通 Release 不读取该入口。
