# WeGit 性能测量记录

更新：2026-10-10。当前包含后台流程与原生新进程启动基线，**不代表全部 UI 性能验收完成**。

## 1. 环境与边界

- Mac16,8，Apple Silicon，24 GiB 内存；macOS 27.0.1（26A434）。
- Swift 6.4 / Xcode 27；Release 优化构建；Apple Git 2.54.0。
- 每项保留 30 个串行样本；中位数使用中间两项平均，P95 使用 nearest rank。
- 文件系统缓存已由 fixture 创建预热。`firstRunMs` 仅是首个测量调用，不能称为操作系统冷缓存。
- Release 应用构建于 04:12:43 完成，fixture 于 04:12:46 就绪，随后开始测量；采样未与该构建重叠。
- 第 3～4 节后台测量包含 Git、解析、显示行/高亮准备和图布局；不包含 SwiftUI 渲染、屏幕滚动或 VoiceOver。原生窗口启动另见第 5 节。
- 源码摘要：`3074da53921f050ae2f6b87776f5c7244e778fe87d167098a15fb204d24c207a`。后续修改与该基线分别记录，不能将旧数据冒充新版 UI 测量。

## 2. 可复现的 fixture

[`create-benchmark-fixtures.py`](../scripts/create-benchmark-fixtures.py) 只创建新目录，拒绝覆盖已有目标；Git 身份、配置与 Hook 均隔离。

| 条件 | 普通仓库 | 大型仓库 |
| --- | ---: | ---: |
| 已跟踪文件 | 1,000 | 100,001 |
| 提交 | 1,000 | 100,000 |
| 分支 | 21 | 21 |
| 改动文件 | 20 | 21 |
| 普通差异源文件 | 80 行 | 80 行 |
| 大型差异源文件 | 无 | 100,000 行，约 11 MiB |

历史使用确定的时间戳、线性提交与 20 个指向旧提交的引用。多分支合并、Octopus 多父提交和浅克隆另由功能测试覆盖；本基线不能替代复杂图的性能场景。

```bash
scripts/benchmark.sh
```

命令会构建 `WeGitBenchmarks`，生成两套 fixture，输出 JSON 原始样本，并保留 fixture 供原生 UI/Instruments 继续测量。输出位于忽略跟踪的 `.build/benchmarks/run-*`。此工具不执行网络操作，不修改用户仓库。

## 5. 原生新进程启动

使用 `WeGitPerformance` scheme 的 Release 构建，通过 `XCTApplicationLaunchMetric(waitUntilResponsive: true)` 记录从进程启动到首帧出现且主线程可响应的耗时。XCTest 的首次预热迭代不计入结果，其余 30 次均重新启动进程；操作系统和文件缓存未清空，因此不称为冷文件系统缓存。

```bash
scripts/benchmark-ui-launch.sh
```

此命令需要可交互桌面，会反复打开并关闭应用。参数域临时关闭仓库和窗口恢复，不改写这些偏好，不自动打开仓库。测试在原生 XCTest 控制下执行；Xcode 给被测 Release 应用附加测试签名权限，测完后必须用普通 Release 构建重新生成交付包，打包脚本会拒绝残留测试权限。

| 指标 | 结果 |
| --- | ---: |
| 样本数 | 30 |
| 中位数 | 434.52 ms |
| P95 | 468.98 ms |
| 最大值 | 598.35 ms |
| PRD 的 P95 预算 | < 1,000 ms，当前测量通过 |

原始样本及构建校验值：[launch.json](performance/2026-10-10/launch.json)。完整结果在 `.build/ui-benchmarks/launch-Q0OcsL/Launch.xcresult`，该目录保留 XCTest 原始指标和被测应用的源码回执。公开样本不包含设备唯一标识。测量环境仍为本机 Mac16,8 / macOS 27.0.1 / Xcode 27，不能替代干净系统上公证包的安装首启验收。

## 7. 完整界面的普通仓库首屏（2026-10-11）

独立 `ReleasePerformance` 配置使用 `org.weopen.WeGit.performanceHarness`，偏好与数据库均隔离。每项 30 次串行采样，每次启动新进程；文件系统缓存保持预热。测试期间没有并发构建。原生窗口/代码绘制后才结束计时，区别于第 3～4 节的后台数据准备。

| 流程 | 中位数 / ms | P95 / ms | 预算 / ms | 结果 |
| --- | ---: | ---: | ---: | --- |
| 仓库外壳 | 301.49 | 313.52 | <500 | 通过 |
| Status 发布与界面绘制 | 160.83 | 277.87 | <300 | 通过 |
| 普通文件 Diff 首屏 | 135.37 | 140.39 | <150 | 通过 |
| History 首批与表格首屏 | 228.04 | 234.64 | <300 | 通过 |

应用本体峰值 RSS 为 **199.30 MiB**，不包含 Git 子进程；这是普通 fixture 的结果。原始数据、源码摘要、边界与样本见 [workbench.json](performance/2026-10-11/workbench.json)，原生结果包保留在 `.build/ui-benchmarks/workbench-2UvCFw/Workbench.xcresult`。

```bash
scripts/benchmark-ui-workbench.sh "$PWD/.build/benchmarks/run-0ojuYG/fixtures/normal" 30
```

上述路径是本机保留的 fixture；其他机器先使用 fixture 生成器创建新目录。`1` 只执行 Smoke，不计入 30 次验收。XCTest 可能通过主窗口菜单重新打开窗口；该动作发生在仓库打开前，不计入外壳指标，也不能据此宣称干净机器安装首启已验收。

普通 Release 不读取性能 Harness 环境变量，不写这些报告。打包必须重新构建普通 Release；构建来源检查拒绝 `ReleasePerformance`。Watcher 的完整事件延迟、滚动、十万级完整应用内存与复杂图仍待单独测量。
