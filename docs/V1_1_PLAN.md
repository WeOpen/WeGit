# WeGit v1.1 功能与交付计划

更新：2026-10-20。目标：补齐日常 Git 工作流中仍需切换 Terminal 的高频操作。用户已授权开始执行四项必选及条件候选的分阶段计划；功能实现、PR/CI 和发布验收分别记录。范围已同步到 [PRD](WeGit_PRD.md) 与 [总计划](PLAN.md)。当前执行 M0 基线收尾，随后进入 M1 Stash。

- 当前 polish 分支已有文件分组折叠、暂存复选框、文件夹树、变更地图、统一工具栏/面板配色和推拉数量；属于已实现待集成内容，先经 PR 与 CI 收尾。

优先级依据是：高频工作价值、现有模块复用程度、数据风险和能否形成完整闭环。当前没有真实 Beta 使用频次数据，因此这是基于产品现状的判断，不是用户调研统计。

## 2. 本版推荐范围

| 顺序 | 功能 | 本版最小范围 | 用户价值 | 规模 / 风险 |
| --- | --- | --- | --- | --- |
| 1 · 必选 | Stash 管理 | 创建、命名、列表、查看差异、Apply、Pop、删除单条；是否包含未跟踪文件由用户明确选择 | 临时切换任务时保存和恢复改动 | L / 高：工作区、暂存区与恢复冲突 |
| 2 · 必选 | Remote 管理 | 查看 fetch/push 地址；新增、编辑、删除仓库级 Remote；在同步前明确当前目标 | 新仓库和地址迁移可在应用内完成 | M / 中：配置与网络目标变化 |
| 3 · 必选 | Tag 管理 | 列表、搜索、查看目标提交；创建轻量/附注 Tag、删除本地 Tag、明确推送单个 Tag | 标记发布版本，补齐版本管理流程 | M / 中：本地/远端引用与已发布标签 |
| 4 · 必选 | 文件历史与定向搜索 | 文件右键查看历史；按路径、作者、时间范围与消息筛选；选中提交复用现有 Diff | 查明某个文件何时、为何改变 | M～L / 中：重命名、分页与查询性能 |

条件候选只有在前四项闭环和回归通过、操作恢复已有足够证据时进入 v1.1；否则整体移到下一版本。不要以“按钮已接入”作为该功能组完成。

## 3. 功能验收与边界

### 3.1 Stash：首个开发项

- 创建前展示将保存的范围，说明暂存状态与未跟踪文件的处理；默认不包含 ignored 文件，不自动为切分支执行 Stash。
- 列表展示消息、原分支、时间和改动文件；差异复用现有阅读器，能区分暂存区、工作区以及包含的未跟踪内容。
- Apply 保留原条目；Pop 成功后才移除。冲突发生时保留条目、展示真实文件状态并进入既有解决流程。Stash 恢复冲突不伪装成可执行 `merge --abort` 的 Merge。
- 提供是否恢复原暂存状态的明确选项；无法恢复时展示失败或冲突，不静默改成另一种模式。
- 删除仅作用于确认的单条；本版不提供一键 Clear。Terminal 增删 Stash 导致编号变化后，刷新并重验实际对象，不能把旧行号当作永久身份。
- 验收夹具：已暂存+未暂存同时存在、未跟踪文件、空改动、重名消息、中文/特殊路径、Apply/Pop 冲突、外部更改列表、取消和失败后的真实状态。

Git 的 Pop 在应用冲突时会保留原条目；Apply 本身不删除条目，产品必须准确表达这种差别。[Git Stash 官方文档](https://git-scm.com/docs/git-stash)

### 3.2 Remote：完成配置到同步的闭环

- 从仓库操作菜单或检查器进入，查看 fetch 与 push 地址、引用规则和受影响的上游分支。
- 写入当前仓库的本地配置；继承配置明确标注来源，不能把一次仓库编辑变成全局配置修改。
- 保留已有多 URL、多 push URL 以及未编辑的配置项；对复杂配置无法可靠编辑的情况，提供只读说明和外部修改入口。
- 保存/删除前重验配置；删除前说明哪些分支会失去远端关联。目标地址变化使旧同步计划失效，重新确认后才能操作。
- 验收：SSH、HTTPS、本地路径、独立 push URL、多地址、非法名称、外部配置变更、取消和凭证信息脱敏。

### 3.3 Tag：建立可靠的版本标记

- 历史提交菜单可创建 Tag；列表能搜索名称并定位到准确的目标提交。
- 支持轻量与附注 Tag；签名沿用用户现有 Git 配置，本版不新增密钥管理器。
- 默认不替换同名 Tag；本地删除与远端操作明确区分。推送指定一个 Tag 并确认 remote、名称及 SHA，不顺带推送所有标签。
- 本版不提供强制移动已发布 Tag 或远端批量删 Tag。
- 验收：同名分支/标签、轻量/附注对象、非法名称、目标提交变化、远端已存在不同对象、签名工具失败、取消/回执不确定时的核对。

已发布标签重新指向其他提交会破坏版本一致性，因此不作为 v1.1 的默认操作。[Git Tag 官方说明](https://git-scm.com/docs/git-tag#_on_re_tagging)

### 3.4 文件历史：复用现有搜索与 Diff

- 在改动列表、历史文件列表进入“查看文件历史”；支持手动输入仓库相对路径，覆盖当前已删除文件的查询。
- 展示路径过滤的分页历史，叠加作者、时间、消息筛选；不是重新建设已有的提交消息/SHA/作者搜索入口。
- 为单文件提供跟随重命名的查询；明确 Git 的检测限制和 Merge 比较基准，不宣称自动追踪任意移动或跨文件复制。
- 点击提交展示该文件相对相应父提交的 Diff；删除、二进制文件、空结果有独立状态。
- 查询在后台执行，可取消；切换仓库或查询条件后，旧结果不能覆盖新上下文。
- 验收：修改→重命名→再修改→删除、Merge、中文及换行路径、分页边界、大型历史和快速连续搜索。先记录现有基线，再核对没有明显延迟/内存退化。

### 3.5 Cherry-pick / Revert：满足条件后交付

- 首版仅单个普通提交；Merge 提交所需 mainline 选择与多提交队列不在本次范围。
- 要求无进行中 Git 序列操作且工作区/暂存区干净，不自动 Stash，不隐式改写远端历史。
- 执行前固定并重验仓库、当前 HEAD、当前分支及目标 SHA，明确即将创建的提交和受影响文件。
- 冲突→外部编辑/标记解决→继续，或中止→恢复原状态，全流程可完成；关闭或重开应用后重新识别实际 Git 状态。
- Hooks、签名失败、空变更与外部操作必须有可解释结果；回执不完整时先核对 HEAD，不自动重做操作。
- 无法完成上述恢复验收时，不开放正式入口，候选整体后移。

## 4. 页面与结构安排

- 主侧栏保留“更改、历史、分支”，随功能落地加入“暂存记录（Stash）”和“标签”。没有实现的模块不提前放占位入口。
- Remote 放在仓库级配置入口，避免占用一个日常主页面。
- 文件历史从文件上下文进入，尽量保持原仓库、文件和提交阅读上下文；沿用现有 Diff 阅读器和查询取消机制。
- Cherry-pick/Revert 放在历史提交菜单和确认面板，沿用操作进度、Activity 与冲突恢复入口。
- Git 行为进入 WeGitCore 服务；UI 不拼 Shell、不维护第二套 Git 状态。复用既有串行写入、仓库身份与目标重验、刷新协调和草稿恢复。
- Stash、Tag、文件历史是不同对象，先各自建立最小模型与服务；不为了这次功能提前建设万能命令框架或 Provider 抽象。

## 6. 后续候选与明确后移

| 项目 | 建议安排 | 原因 / 提前条件 |
| --- | --- | --- |
| 提交消息历史 | 首选小型追加项，必选闭环完成后评估 | 改动较小；应按仓库保存、可清空、去重，不自动覆盖当前草稿 |
| 图片前后对比 | v1.1.x 候选 | PNG/JPEG 原图并排、尺寸/大小与解码上限；图片滑杆、SVG 渲染独立评估 |
| 显式签名设置 | v1.1.x 或之后 | 保留现有签名兼容，新增 GUI 需先补真实 Pinentry/工具缺失路径证据 |
| Reset / Reflog | 后续独立设计 | 不与“用新提交撤销”的 Revert 混淆；涉及工作区和历史改写，先明确恢复边界 |
| 内置三方冲突编辑器、Interactive Rebase、选中行暂存、Blame | 保留 v1.2 方向 | 需要独立的文本/补丁正确性与冲突恢复工作，不挤入日常补全版本 |
| Worktree、Submodule、LFS | 保留 v1.2 方向 | Worktree 当前被明确拒绝打开；需处理共享引用/配置、独立 HEAD/index、跨工作区协调与监视 |
| GitHub/GitLab PR/MR、AI 提交信息、自动更新 | 独立需求评审 | Provider 权限、数据传输、分发信任/更新签名均扩大当前范围 |

如果下一版首要用户场景确定为 Codex 多 Worktree 并行开发，应重新排列版本目标，把“可靠打开已有 Worktree”作为一项独立能力，并相应移出其他必选项；不把它当作几行路径兼容修复。Git 明确区分每个 Worktree 的 HEAD 与共享引用/配置。[Git Worktree 官方文档](https://git-scm.com/docs/git-worktree#_refs)

## 7. 开发与发布约束

- 每个必选功能对应一个需求 Issue，可按 Core / UI / 验收拆 PR；默认沿用现有 V1.1 milestone，不新增版本号承诺。
- 新写操作用私有临时仓库/本地 Bare Remote 校验；不访问个人仓库、真实凭据或全局 Git 配置。真实网络兼容性与本地夹具结果分别记录。
- 按当前约定不在本地执行 XCTest；核心专项可使用独立检查，原生交互使用隔离预览与人工路径，UI 测试目标可编译。需要实际 XCTest 的回归安排到合适的托管 CI，未跑项保持待验。
- 辅助功能完整验收继续按用户决定暂缓，不重新加入本版功能优先级。现有安装/迁移、性能、Beta、兼容性遗留项继续保留实际状态，不借版本更换视为关闭。
- v1.0 的一次性发布例外不自动覆盖 v1.1；发布前单独核对仓库既有 workflow 的要求、当时的环境与实际证据。计划文档不修改发布门禁，也不把构建或局部预览当作完整验收。
- 最终先形成 v1.1 Beta，固定源码和制品来源，针对实际反馈修复后再发布 v1.1.0。不自动向用户发送邀请。
