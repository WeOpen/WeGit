## 2. 已实现的可运行能力

### 工程与状态

- SwiftUI 主窗口、原生菜单、工具栏、设置和可选 Inspector。
- 应用级状态、每窗口选择状态和每仓库 Session 分开管理。
- SwiftData 最近仓库与收藏，独立偏好，按仓库保存提交草稿。
- 打开目录、拖入目录、启动恢复和路径无效提示。
- Git 检测、版本检查与下次启动使用的自定义可执行文件选择。

### Git 执行与可靠性

- 直接 `posix_spawn` 执行参数数组，不用 Shell 拼接应用命令。
- 独立进程组、双管道并发读取、标准输入关闭、输出上限、超时与取消。
- 显式 FIFO 异步许可跨 `await` 持有；排队取消与异常释放经过测试。
- 字面路径、NUL 状态/路径参数和仓库相对路径校验。
- 写入前校验 HEAD；UI 操作还固定分支身份，拒绝同一提交上的外部分支切换。
- 活动摘要不保存代码、补丁和提交消息；OSLog 与性能 signpost 已接入。

### 首个提交闭环

- 已暂存、未暂存、未跟踪、冲突与同文件双重状态。
- Unified/Split 差异、替换行对齐、基础词法高亮与二进制提示。
- 按区域展开/折叠未变更行；大差异摘要、显式读取、取消、内存分页及磁盘分页。
- 文件/全部暂存和取消暂存，未诞生分支取消暂存。
- 标准差异块暂存/反向取消暂存，过期差异拒绝应用。
- 已跟踪文件的未暂存内容丢弃与确认。
- 普通提交、消息型 Amend、Hook 失败与已有 SSH 签名配置兼容。

### 后续阶段的早期实现

- 分页历史、提交对象的长度协议读取、提交图、父提交差异。
- 本地分支创建/切换/重命名/删除、跟踪与上游设置、Merge 和基础冲突恢复。
- 明确目标的 Fetch/Pull/Push、固定 Lease、两步 Commit & Push 与受控 AskPass。
- FSEvents、合并刷新、恢复应用焦点校验和过期请求过滤。

这些实现不等于 Phase 7～11 已整体验收。大型历史、原生界面回归、真实远端认证与完整配置矩阵仍需验证。

## 6. 第二轮：克隆流程与恢复

更新：2026-10-07。按 Phase 2～3 的早期未完成项继续，保留 0.1.0 开发预览版本。

### 实现

- `CloneCoordinator` 负责命令、目录创建、取消、结果校验和恢复凭据；Clone View 不再构造 Git 命令。
- `ProcessRunner` 支持增量 stderr 回调；解析跨数据块的 CR/LF 进度，只向 UI 输出已识别的阶段与阶段百分比。
- 新建目录使用原子 `mkdir`；已有目录、文件和符号链接一律不接管，即使目录为空。
- 失败后记录目录归属、文件身份及元数据快照，不自动删除。移到废纸篓前重新核对；新增文件、目录替换或其他变化会拒绝清理。
- 快照不跟随子符号链接，使用相对路径枚举避免 macOS 临时目录路径别名造成误判。超过 20,000 项或无法完整读取时仅保留 Finder 处理入口。
- 克隆成功后打开仓库期间继续保持忙碌状态，避免重复启动和旧任务覆盖新任务。
- 取消、超时和进程启动失败写入 Activity；没有实际退出码时保存 `nil`，不虚构退出码。
- 仓库地址、保存位置、错误、重试和恢复提示保留在可观察的克隆状态中；嵌入 HTTP 凭证或敏感查询参数的地址在执行前被拒绝。

目录核对与系统移动不是跨外部进程的事务锁。最终动作使用 macOS 废纸篓，不做递归永久删除；测试不承诺抵御拥有同等文件权限的外部进程在检查与移动之间的恶意竞争。

## 7. 第三轮：状态与差异边界

更新：2026-10-08，继续 Phase 4～6。

### 实现

- 差异读取支持 3、20、80、200 行上下文及忽略空白；读取选项随快照保存，应用补丁时使用相同基准。
- 忽略空白是只读展示模式，领域层也拒绝把过滤后的补丁用于暂存或丢弃。
- 差异块丢弃仅允许未暂存层，确认显示文件和块范围；其他块与暂存区内容保持。
- 每个块必须属于重新读取的当前差异；拒绝过期、伪造或不支持的块。
- 读取补丁固定路径前缀、增删符号并输出完整对象 ID，避免用户的 Diff 显示配置改变应用目标。
- 严格检查 NUL 终止状态、差异块行号、行数、行尾标记和截断数据；超范围行号返回错误，不强制解包崩溃。
- 普通代码中的 “Binary files” 文本不会误判为二进制。一个路径对应多个补丁或 combined diff 时使用只读原文预览。
- 取消暂存重命名文件时同时恢复新旧索引路径。
- 未跟踪预览不会跟随符号链接；普通文件采用限量读取并核对版本，管道等特殊文件直接拒绝。
- 暂存/取消暂存后重新核对选中文件所在层；文件没有剩余改动时清除详情。
- 每次 Diff 请求具有独立 ID，旧请求的成功、错误和 Loading 收尾均不能覆盖新请求。
- 筛选无结果使用明确空状态和清除入口；读取失败提供重试和恢复默认选项。

## 8. 第四轮：词级差异与分栏刷新

更新：2026-10-09，继续 Phase 5。

### 实现

- 新增可切换的词级差异，在替换行中突出变化的词、数字、标点和空白；删除与新增分别使用划线和下划线辅助表达。

## 19. PLAN 复核：推送未知结果与恢复

更新：2026-10-10。复核计划中的未勾选任务，将已实现但待组合验收的条目与尚缺能力分开，并继续 Phase 9 的结果恢复。

### 实现

- Push 非正常结束后，只有完整、单一且对应本次 refspec 的 `[rejected]` / `[remote rejected]` 回执被当作明确拒绝；`[remote failure]`、截断回执、超时与取消保留为未知结果。分类依据见 [Git 推送状态格式](https://git-scm.com/docs/git-push#_output)。
- `PushOutcomeUnknown` 保留确认时的内存计划，`PushReceipt` 保存仓库实体、目标引用、提交和地址指纹，不保存 URL 或凭据。用户主动核对时，只查询确认的推送地址及引用；本地 HEAD 已变化也可以核对原提交。
- 关闭/重启后，只有仓库实体和实际地址指纹仍匹配才重建只读核对计划。配置地址改变、换了仓库，或移动仓库改变了相对地址时，在发起网络查询前拒绝；不会查询新的同名 Remote 作为原目标。
- 凭据、查询参数或片段出现在地址中时，不保存其派生指纹。该类地址在当前窗口可使用内存中的原计划核对；重启后需要用户手动核对原目标并明确标记已处理。
- 核对匹配时只确认“当前远端目标指向本次提交”；目标不同或缺失不证明此前未成功。只有用户选择重新准备并再次确认后才能发起新推送，Force With Lease 需要重新选择和确认。
