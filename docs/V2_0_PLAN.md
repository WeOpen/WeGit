## 1. 真实目标与成功标准

v2.0 先完成客户端基础能力。用户可以在应用内建立或克隆仓库、选择改动、整理提交、比较与移植修复、处理冲突、切换任务、管理关联仓库、找回仍可恢复的数据，以及安装和更新应用。后续版本再增加协作、AI 或新的任务工作流。

“功能齐全”按下列工作流判断，不能只按菜单或 PR 数量判断：

1. **正常流程完整**：每项功能有真实入口、预览、执行结果和下一步；现有 v1.2 功能继续可用。
2. **失败与恢复完整**：取消、外部 Terminal 修改、Hooks/签名失败、回执丢失、切换及重开不会丢草稿、覆盖未选内容或引导重复写入。
3. **日常操作可在客户端完成**：常规操作不依赖复制终端命令完成最后一步；明确不支持的文件、仓库或高级 Git 语义保留可理解的边界。
4. **界面符合层级**：导航与控制层使用适当 Liquid Glass，内容层稳定可读，核心操作有原生键盘和焦点路径。
5. **开销可验收**：沿用既有性能预算；新功能先固定规模和预算再实施、采样，不用缓存后的结果或后端样本替代整应用性能。
6. **客户端与网页联动完整**：网页主题可直接唤起客户端导入，客户端保留多个自定义主题；官网自动取得有效版本，选择适用安装包并提供手动切换。
7. **交付可追溯且高效**：同一源码提供三种 DMG，下载/迁移/回退各有真实结果；重校验按完整开发批次触发，子任务之间不逐项等待 GitHub。

本版集中交付；内部按真实用户流程组成开发批次，一个批次可以覆盖多个子任务和 Issue，以批次形成 PR、统一验收。子任务实现后记录进度并继续，不逐项发起 GitHub 重校验。所有 V20 模块均属于本版范围，优先顺序不表示可静默省略；范围调整需更新本文和 PRD。

### 2.2 继承的约束

- 复用 Git CLI、Credential Helper、SSH Agent、Hooks 和已有签名工具；Git 核心保持无新增第三方运行时依赖。
- 同一工作区和 common directory 的协调范围分别保持；所有写入固定对象/身份/快照，参数数组与字面路径进入服务层。
- Git 写入验收只使用私有临时仓库、本地 bare remote、隔离配置/密钥/偏好；不借测试操作个人仓库或系统保护设置。
- v2.0 保持 macOS 26+，新增 Apple Silicon/Intel 单架构包并保留 Universal。现有 v1.2 的实机/安装/VoiceOver/整应用性能/反馈延期保留实际状态，不重开已完成开发或写成已通过。
- 继续 GitHub Releases＋项目网站、正式标识 `com.willxue.wegit`、ad-hoc/未公证路线；Developer ID/公证仍是可选升级。更新来源认证独立设计。
- 原生页面少用次级标签与重复说明。对象、作用域和不可恢复影响集中在真正需要用户决策的确认中。
- 本机不执行 XCTest。开发检查按真实修改范围分流；阶段/版本的实际原生验收在托管环境独立安排。

## 4. 每项开发范围与验收

### V20-01 · Liquid Glass 与原生界面

**目标**：修正当前玻璃样式从主窗口、Settings 和 Sheet 扩散到普通内容按钮的问题，保留原生控件行为与 R5 纸墨/朱砂/青瓷的设计特色。

- `01a`：建立按用途选择的控件规范。主窗口/Sheet 的内容按钮默认使用普通系统样式；主要操作用实色突出样式，密集行内动作用轻量样式，工具栏/浮动导航按上下文采用玻璃。
- `01b`：收敛 `workbenchControlFamily`、主要操作、图标、菜单和 Tabs；移除内容层的全局玻璃继承及内容面板的重复玻璃。保持快捷键、role、responder 验证、禁用值与完整点击区域。
- `01c`：检查系统工具栏与自定义表面，避免玻璃叠玻璃；浮动控制条按真实层级判断，不按顶部/底部位置一刀切。
- `01d`：逐页替换和渲染检查。Diff/Blame 代码、文件/提交列表、表格、输入区和普通表单使用稳定内容材质；标准 Material/NSVisualEffectView 仍按其用途使用。
- `01e`：滑块、开关等瞬时交互效果遵循系统行为；减少透明度/动态效果、增强对比度和自定义主题的退化路径保持明确。

**验收重点**：正文后方内容变化或滚动时不产生装饰性折射；导航仍清楚；实际键盘、焦点与按钮命中正常。需要实际页面截图与操作，不能仅搜索 `.glass` 数量宣告完成。

官方依据：[HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[WWDC26 SwiftUI Group Lab](https://developer.apple.com/videos/play/wwdc2026/8120/)。这是设计使用边界，API 可作用于任意 View 不代表任意内容都适合玻璃。

### V20-02 · 仓库建立、克隆与打开

- `02a`：从 Welcome/仓库菜单建立普通仓库，选择目录与初始分支；已有普通文件可保留并作为未跟踪内容显示，拒绝覆写已有仓库或隐式建立嵌套仓库。
- `02b`：克隆支持明确选择分支、仅指定分支、深度与递归 Submodule；默认行为保留现有完整克隆，浅仓库支持显式补深/获取完整历史。高级选项显示实际下载与历史边界。
- `02c`：目录移动、权限/书签失效、Unborn/Detached HEAD、clone 部分完成、网络取消与磁盘不足均可核对。清理限定本次创建且身份未变化的目录。

**验收重点**：空目录/已有文件/已有 `.git`/嵌套路径、中文/换行路径、浅历史边界、认证取消及部分克隆；当前工作区、真实文件和用户配置保持正确。

### V20-03 · Reset、Reflog 与恢复

- `03a`：从历史/分支进入 Soft/Mixed/Hard Reset，预览当前分支、固定目标、索引/文件影响和发布历史状态。默认建议保留内容的模式，破坏性模式单独确认。
- `03b`：浏览有界的 HEAD/分支 Reflog，识别条目时间、动作及对象是否仍存在；支持从旧提交创建恢复分支、找回误删分支和撤回最近本地提交。
- `03c`：定义工作文件备份、恢复定位记录与保留/清理规则。破坏性操作前备份目标内容并核对成功；恢复入口固定备份身份、作用域和实际存在的对象。
- `03d`：覆盖外部引用移动、特殊索引标记、Unborn/Detached、多 Worktree 占用、取消及未知回执；不把共享分支 Reset 写到错误工作区。

**验收重点**：逐字节核对 HEAD、索引和文件；恢复分支的提交可达。Reflog 依赖对象保留，未提交内容依赖备份；界面不能统一承诺“全部可撤销”。

### V20-04 · 任意比较与范围

- `04a`：选择两个提交/本地分支/远端跟踪分支/Tag 进行两点比较，先解析并固定实际对象；保留现有父提交比较作为默认快捷入口。
- `04b`：提供“共同祖先到目标分支”的范围比较，显示方向、共同祖先、待合入提交和文件；明确两点与共同祖先比较的不同语义。
- `04c`：支持文件筛选、重命名、根提交、Merge 多父和有界分页，复用 Unified/Split、磁盘差异与原文复制；缺对象/浅历史边界提示显式获取，不自动下载。

**验收重点**：分叉/已包含/无共同祖先/多个共同祖先、移动引用、重命名与大差异；比较不写仓库，旧异步结果不能覆盖新对象。

### V20-05 · 文件处理与忽略

- `05a`：按原始差异选择行丢弃，支持预览、取消和备份恢复；默认仅修改工作文件，保留未选变化及索引。继承 v1.2 的替换行、CRLF、末尾换行、Unicode 和陈旧选择保护。
- `05b`：从历史/比较恢复明确时点的单文件，区分恢复到工作文件、恢复到索引及两者；默认仅恢复工作文件。固定路径/blob/模式，处理删除、重命名、二进制和符号链接边界。
- `05c`：未跟踪文件可添加精确文件/目录/扩展名忽略规则，选择仓库 `.gitignore` 或本地 `.git/info/exclude`；预览匹配范围、转义和规则位置，保留注释/行尾/原有规则。

**验收重点**：其他索引项与未选文件不变；被忽略目录、文件/目录替换和符号链接父目录有独立保护。忽略规则不会自动移除已跟踪文件。

### V20-06 · 多提交与 Merge mainline

- `06a`：历史中选择有序的多个提交，预演 Cherry-pick/Revert 队列的顺序、当前分支及实际文件落点；执行前固定全部提交和起点，不默认自动 Stash。
- `06b`：Merge 提交提供可理解的 mainline 父提交选择与对应差异；不把用户分支恒定解释为 OURS，也不根据显示顺序猜父提交。
- `06c`：记录已完成、当前与剩余提交；重复冲突、空变更、edit/消息停点、Hooks/签名失败和重开形成继续/跳过/中止闭环。队列部分成功或回执丢失后先核对，不整批重试。

**验收重点**：普通与 Merge 混合队列、父提交选择、重复冲突、外部 todo/HEAD 修改、空提交与取消；旧提交仍可定位，中止的实际恢复范围准确。

### V20-07 · 补丁导入与导出

- `07a`：导出任意比较、选定文件及已暂存/未暂存的原始补丁；支持 Git 文本/二进制补丁，二进制仅文件级。导出普通补丁与 `format-patch` 提交邮件格式分别命名。
- `07b`：导入标准补丁，显示路径、状态、目标层与预检查结果；默认应用到工作文件，应用到索引为明确独立选择。写入前重验原始字节、索引和路径，不从高亮文本重建补丁。
- `07c`：导入单个/有序邮件提交补丁，使用受控 Git am 序列，预览作者/提交信息及文件；提供冲突继续/跳过/中止和重开识别，区分 Git am 与其他 rebase-apply 状态。

**验收重点**：导出/导入往返字节和模式一致；路径越界、忽略内容、重命名、CRLF、损坏/截断/大补丁及部分成功均有准确结果。应用文件变化不能报告成已创建提交。

### V20-08 · 临时任务与提交消息

- `08a`：从选定 Stash 创建分支，固定对象/起点/分支名；Apply 成功后才按明确选择删除记录，冲突及删除回执不确定时保留可核对状态。
- `08b`：显式“保存当前任务并切换”，预览跟踪/未跟踪范围与目标，保留索引状态和草稿；保存成功、切换失败分别报告，不自动重复保存或丢弃。
- `08c`：按仓库保存可清空的提交消息历史，去重并保护当前草稿；支持消息模板，读取配置来源和有界原文。模板/历史只填入编辑器，提交仍明确触发。

**验收重点**：Stash 外部增删、目标变化、混合暂存、忽略内容、失败重开、空/长/多段消息；保存、切换和提交分别核对真实状态。

### V20-09 · 图片与特殊内容

- `09a`：PNG/JPEG/WebP 两侧图片对照、尺寸/大小、缩放/平移及滑杆比较；透明图片有可读的背景，内容图像和颜色保持原样。
- `09b`：普通图片、二进制、大文件和 LFS 指针分别展示；固定两侧对象，先检查压缩字节和解码像素预算，大图先缩略预览，原尺寸明确加载且可取消。
- `09c`：特殊编码文本可明确选择阅读编码，解码失败/截断/无法可靠构造部分补丁时保留原始导出及文件级操作；不把替换字符后的显示文本写回仓库。

**验收重点**：损坏图、透明图、超大像素、缺失一侧/对象、快速切文件、LFS 获取取消、非 UTF-8/无末尾换行；旧解码不覆盖新上下文，预览不触发整库下载。

### V20-10 · 配置、签名与验证

- `10a`：扩展仓库级 GPG/SSH 签名设置、现有密钥标识与工具检测，显示有效值/来源/继承/工作区覆盖；不存储或生成用户私钥。
- `10b`：提交和 Tag 签名结果可查，区分验证通过、无签名、无公钥/无法验证、无效与信任不足；不把密码学有效等同于已信任身份，不自动联网获取密钥。

### V20-14 · 自定义主题库与网页直达导入

- `14a`：客户端保存多个自定义主题，支持新增、复制、重命名、编辑、删除、导入/导出和切换。主题使用稳定 ID，名称可重复而不会覆盖另一条；删除当前主题有明确回退，切换/重开后保留选择。
- `14b`：旧 `customTheme` 迁移为主题库的一项，保留原17角色颜色、控件外观与当前选择。主题库有独立的存储版本/activeThemeID；对外 JSON 继续兼容客户端 v1 的 version/name/controls/colors，不把库元数据混入导出文件。
- `14c`：注册受控 `wegit://theme/import` 入口，从用户点击网页动作直接唤起客户端。解析/校验后保存为新主题并显示导入结果，启用主题为明确动作；重名、重复请求与不同内容分别处理，不自动覆盖现有主题或打断 Git 任务。
- `14d`：网页预览、下载JSON和发送客户端使用同一份当前编辑后的配色快照，包括强调色/对比度，不能只传目录ID再读取原配色。提前准备 `wegit://theme/import?v=1&data=<base64url-json>&sha256=<hex>`，在用户点击手势中直接唤起，不先等待网络；客户端只接受限定主题动作并核对字节/格式/摘要。SHA只证明一致性，不证明来源身份。
- `14e`：网页常规主题直接导入；未安装、旧版不支持协议或浏览器阻止唤起时提供下载客户端/JSON的可用退路，不虚报“导入成功”。验证冷启动、已运行、多窗口、恢复尚未完成、重开、重复点击、恶意/损坏负载及取消预览，保留草稿与活动任务。

**数据与界面契约**：主题库为应用级共享，编辑预览与当前激活主题分别保存，取消不会改变原选择。主题文件沿用现有64 KiB上限；URL使用归一后的JSON，解码负载上限8 KiB、完整URI上限16 KiB，超限提供文件导入，不截断。无任意文件写入、代码执行或任意远端抓取入口。主题卡片保持名称、必要预览与当前选中状态，避免重复说明。

**验收重点**：预览/下载/URI/客户端保存的17色与controls一致；同名主题不互相覆盖，1/10/100条库切换与冷启动有性能样本。旧主题格式、跨窗口预览/删除、重复/陈旧导入的归属明确，所有写入用隔离偏好。

### V20-15 · 官网自动版本和下载选择

- `15a`：扩展现有 Release 读取/选择逻辑，使用结构化的版本/通道/minimumOS/架构/URL/摘要/大小/manifest 数据。按语义版本选择已公开且制品完整的版本，过滤 draft；稳定与候选通道明确，不能跨版本拼接三种包。
- `15b`：Release 发布/编辑/撤销触发有界的轻量清单更新；即使没有 site 提交，官网也能取得新版本。复用已有部署路径、缓存/ETag与最后有效清单，正常服务下目标在发布后5分钟内可见；兜底刷新不变成每个访客直接请求GitHub或页面持续轮询。
- `15c`：网页自动推荐对应包，优先使用可获得且可信的架构/位数信息：Client Hints 的 arm+64归一为arm64，x86+64归一为x86_64，再选择Apple Silicon/Intel。缺失/含糊/不支持/翻译环境回退Universal；不把 `navigator.platform` 的MacIntel或UA里的Intel当作CPU证据，不引入WebGL探测或性能测试指纹。
- `15d`：三种包始终可手动选择；用户选择优先于后到的自动识别。自动选择推荐项，下载由用户动作触发；无JS/非Mac/识别失败仍可取得Universal或其他手动包，缺少有效摘要/来源的资产不作为下载。
- `15e`：覆盖新Release但无site提交、旧稳定仅ARM/ZIP、公开Universal候选、三包齐全稳定版、部分资产上传/撤销、缓存陈旧、失败兜底及手动覆盖；不将不适用架构或候选误标成稳定。中英文版本/大小/链接一致，Codex浏览器和Ego Lite实际核对下载与唤起，缺架构信息路径仍可用。

**现有与新增**：网站已有构建时读取Release及Universal DMG选择；本项补齐可靠刷新、三种变体、通道/版本排序和自动架构选择。网页无法保证总能知道真实硬件，信息不足时选择Universal是本版的正确完成行为。依据：[MDN Client Hints](https://developer.mozilla.org/en-US/docs/Web/API/NavigatorUAData/getHighEntropyValues)、[UA reduction](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/User-agent_reduction)。

**三种制品契约**：文件名为 `WeGit-X.Y.Z[-rc.N]-macos-{universal|applesilicon|intel}-adhoc.dmg`，各有`.sha256`和对应变体manifest；顶层release清单关联同一版本全部变体及签名。先完整上传/核对再公开，继承旧单一manifest/ZIP版本的读取兼容。Universal验收一次的Core/Git/GPG结果不能复制成三次测试数，也不需为每个薄包重跑相同后端；三包各自核对编译/架构、签名、资源和完整性。

### V20-16 · 批次验证与开发效率

M0 已实现草稿/中间 head 延后、明确批次送验、可信方法集合及输入回执复用；工具检查通过，实际 GitHub 频率与托管执行另行验收。基线集合不代表新增功能通过。

- `16a`：按完整用户流程/功能批次组织分支和PR，一个PR可关联多个子任务/Issue。子任务不单独触发验收或等待远端，进度先标为“实现完成/待批次验收”，批次结果统一映射覆盖范围。
- `16b`：M0先调整工作流触发/排队规则：草稿及开发中间提交不自动启动后端重流程，批次稳定后进入待审状态或发出明确验收请求。正常审入可信批次入口，一次smoke后执行该批次已注册的明确方法集合，避免每个方法重建/重跑smoke。轻量策略检查保留，正式集成仍取得该head所需真实结果，不删除必需项或将未验收报绿。
- `16c`：开发遇到错误时按需做局部定位；视图/网站/工具及Core测试编译按批次实际范围集中执行。纯文档先按文件类型识别，包括site/README，不因site前缀触发整站构建。后端重校验只在包含真实后端代码的稳定批次安排一次，本机仍不运行XCTest。
- `16d`：缓存构建与依赖；按应用/后端/测试/夹具/验证入口的不可变输入复用已通过回执，前端/文档不重复Core/GPG/后端性能。三种分发共用相同源码的后端结果，分别核对包；合入main后按输入等价关联证据，不将旧SHA或skipped当作通过。
- `16e`：批次送验后保持候选head稳定，在独立后续批次继续无依赖开发；取消失效重复队列，避免等待每个子任务。最终固定候选集中执行一次完整验收；失败修复只补受影响范围，改变共享契约/覆盖不足时扩大回归，保持精确来源。

**验收重点**：多个子任务/草稿提交不会产生对应数量的重run；批次/最终验收对固定head真正执行，混合范围不会漏后端，未知范围阻断分流而不默认启动长流程。记录每批次实际run数、队列等待、耗时与缓存/证据复用；质量结论来自覆盖清单，不来自运行次数。当前workflow仍监听每次PR更新，只有落实此模块才能改变实际频率。

## 7. 技术契约与复用边界

- **View → App 状态 → 领域服务**：视图表达意图，服务构造 Git 参数并判断权威结果。新增读/写意图分别接入；UI 不能直接运行 Process。
- **窗口 → 工作区 → common directory**：页面/选择按窗口；仓库真实状态与草稿有工作区身份；引用/配置共享范围单独协调。锁顺序和关闭订阅在多窗口前验证。
- **固定对象与快照**：所有预览绑定 OID、HEAD、索引、路径/文件身份及配置来源；执行前重验，引用名或显示行不作为写入身份。
- **字节与呈现分离**：忽略空白、高亮、换行、阅读编码与图片缩放仅影响展示；写入使用原字节/对象/模式，危险文件保留文件级路径。
- **恢复状态独立持久化**：备份、序列进度、未知回执和迁移记录有版本/作用域/身份；确认与失败宿主不依赖可被重建的 Diff 子视图。
- **有界后台工作**：历史/搜索/图片/补丁分页或限额；取消后旧结果失效。多个窗口聚合事件，不增加持续 Status 轮询或重复共用目录监视。
- **配置范围显式**：编辑白名单、来源和写入作用域可核对；工作区覆盖、include 与多地址保留语义，不简单覆盖继承来源。
- **主题格式与库分别版本化**：导入/导出保留v1主题JSON，库使用稳定ID/activeThemeID；网页发送当前配色快照，URI是限定数据入口，不能成为任意命令或抓取通道。
- **版本选择与架构选择分离**：先选公开且完整的版本/通道，再选同版本变体；自动推荐不覆盖手动选择，不能混用不同版本包/校验/manifest。
- **分发独立信任**：更新器的来源签名、macOS 系统信任、制品完整性分别核对；安装失败不修改安全设置。选择更新运行时前记录许可、额外依赖和 Universal 包开销。

## 8. 性能预算与生产开销

### 8.1 既有预算

| 普通 Release 指标 | 保留的 p95 预算 |
| --- | ---: |
| 工作台外壳可用 | < 500 ms |
| Status 首屏 | < 300 ms |
| Diff 首屏 | < 150 ms |
| History 首屏 | < 300 ms |
| 稳定外部事件到可见更新 | < 1000 ms |
| 启动可响应 | < 1000 ms |

已有模块的 2000 ms 后台入口、500 ms 取消，以及按各自夹具定义的 RSS/扫描限额继续沿用，不将后端预算套成整应用已验结果。普通/大型仓库的尺度和原始数组见 [性能记录](PERFORMANCE.md)及 [v1.2 最终证据](acceptance/2026-11-03/v1-2-final/README.md)。

### 8.2 M0 必须冻结的新预算

| 场景 | 需要固定的规模与指标 |
| --- | --- |
| Reset/文件恢复/补丁/多提交 | 文件数、字节、提交数；首次预览/执行 p95、取消延迟、备份空间与清理上限 |
| 任意比较/统一搜索 | 提交/引用/路径规模、首批/下一页、快速切换、峰值 RSS；同时记录首次对象准备 |
| 图片 | 单图压缩字节/像素、双图同时解码、缩略缓存与原尺寸峰值；内存峰值和切图取消 |
| 多窗口/Worktree | 1/2/4 个窗口、相同/不同工作区，监视/进程数量、空闲 CPU、事件合并与共享写入延迟 |
| 更新/迁移 | 元数据/下载上限、签名验证与迁移开销、旧包/备份所需空间、启动阶段的额外延迟 |
| 主题库/网页导入 | 1/10/100条主题，URI 8/16KiB及文件64KiB边界，冷启动/切换/预览/迁移开销，避免逐项重建所有主题预览 |
| 官网版本/架构 | 有界清单、缓存/ETag、发布后正常5分钟可见目标，架构提示只查询一次；无每访客GitHub请求、常驻轮询或WebGL探测 |
| CI开发开销 | 每个稳定批次的实际重run数量、等待/耗时、构建缓存和证据复用；多个子任务不产生对应数量的重复重流程 |

新入口优先采用已有同类预算作为起点，冻结具体值与夹具后才进入实现。预算变更必须基于功能规模、依赖增量和实测说明，在验收前同步记录；不能在失败后单纯放宽门槛。

当前v1.2 Universal DMG为20,984,079下载/59,508,178安装bytes。v2.0对三种包分别测量，默认每包30MiB下载/60MiB安装预算；新依赖增量在M0测算和记录，不在失败后临时放宽。官网沿用静态资源/客户端JS/Worker预算，只发布清单和下载URL，不把三个DMG复制进网站资源。

每个指标至少 30 个有效串行样本，保留全部原始结果、设备/缓存条件和失败。滚动用真实轨迹、帧/卡顿与 RSS，不能用全零指标证明流畅。玻璃减少、缓存或子进程 p95 不能替代原生界面/整应用实测。

## 9. 批次验证、范围分流与证据

### 9.1 校验频率

1. **子任务实现期**：完成代码与进度记录后继续下一项，不创建独立GitHub验收、不等待每个子任务的重CI。出现实际错误时按需做局部定位。
2. **业务批次稳定期**：多个子任务构成用户可操作的完整流程后，对固定head集中编译/行为检查并提交一次批次验收。已通过输入/范围复用，等待期间继续无依赖的后续批次。
3. **最终候选期**：固定完整版本候选集中执行一次完整验收，三种包共用同源码的后端结果。失败修复补受影响范围，共享契约变化或覆盖不足时扩大，不机械重跑全部已通过范围。

此频率是用户的最新执行要求。M0先实现V20-16的触发、可信批次用例集合与证据复用；只改文档或减少Issue数量不能改变现有每次PR更新触发的实际运行。

### 9.2 按实际改动分流

| 实际改动 | 默认开发检查 |
| --- | --- |
| 纯文档 | 轻量链接/锚点检查与差异格式检查 |
| 原生 View、展示/本地化辅助、品牌 | 相应视图/UI 测试源编译；需要视觉结论时做真实原生预览/页面操作 |
| site | 网站 Node/Python 测试、构建、原资源预算、Wrangler dry-run、本地 Worker 校验 |
| CI/工具 | 相应工具与分流契约检查 |
| 只改 Core/后端测试源 | 编译测试目标，实际执行依托管安排 |
| 真正后端业务/执行/基础设施、AskPass、Package 或明确业务 App 状态代码 | 稳定批次集中执行受影响Core/Git/签名/性能，未变输入复用；包校验在集成候选/发行制品集中安排 |

后端范围以 [AGENTS.md](../AGENTS.md)和 [change_scope.py](../scripts/ci/change_scope.py)的正向名单为准。混合改动只在包含真实后端代码时增加长流程；无法确认 Git 范围则修正读取并阻断分流，不能默认启动重校验。手动 workflow 默认验 site，只有明确选择时增加后端校验。

纯文档按全部文件类型判定，包含site目录下的Markdown也只查链接；只有真正网站源变化才进入网站批次。主题库若修改AppPreferences等业务代码，按实际依赖验收，不能因为功能名叫“主题”就忽略后端；未变的Git/GPG输入可复用。

实际XCTest在托管环境执行。可信批次入口正常审入main后，对固定SHA执行一次smoke及该批次明确注册的专项集合，复用同次编译/启动条件；不为每个子任务独立dispatch。smoke仍须实际1/1、0失败/跳过，保留源码、日志、xcresult、截图和环境回执，不放开任意候选脚本。

最终功能矩阵按全部 V20 子任务和 v1.2 回归基线冻结，实际执行数必须与清单一致。阶段/最终验收独立安排，不因纯 UI/文档 PR 自动重复 Core/GPG/包流程；源码等价时可按输入 SHA 复用已核验的后端来源，新增 UI 行为仍需自己的实际证据。

关键数据夹具包括空/Unborn/Detached、分叉/Merge/浅历史、多工作区、中文/空格/换行路径、CRLF/无末尾换行、符号链接/ignored 内容、特殊索引、外部编辑、Hook/签名失败、网络/工具缺失与取消。普通和大型仓库分别保留结果；不增加镜像实现的无效测试。

## 11. 范围冻结与后续功能

本版冻结为通用Git客户端及基本网页联动：普通仓库/Worktree、Submodule/LFS常用管理、历史/改动/同步/恢复、图片/补丁、原生效率、多个主题/网页导入、更新/三架构分发和自动版本下载。Bare写管理、任意plumbing、Sparse Checkout、LFS历史迁移/服务端锁定等专门工作流不作为通用基线；阻断本版已列流程时补齐范围并更新本文。

v2.0 完整交付后，Bug、性能、安全和兼容性用维护版本持续处理。后续主要功能围绕一个可感知的新工作流组织，例如 GitHub/GitLab PR/MR 审阅协作、可选 AI 差异/提交辅助、图形化 Bisect、Worktree 任务编排；这些不再挂在 v2.0 的交付清单中。

发布日期和工期在任务拆分、预算与验证资源明确后估算；不按模块数量猜日历日期。实际开发已经开始，[进度](V2_0_PROGRESS.md)与[冻结契约/预算](V2_0_CONTRACTS.md)分别记录；不提前宣称客户端验收或修改发行状态，不建立 heartbeat。
