# 第二轮界面设计优化

日期：2026-10-13。设计方向为“分支连接”：将已有 W 标记、提交图和原生组件串联成一致的视觉语言，增加辨识度，同时保留高频阅读与键盘操作的稳定性。

## 设计与实现

| Severity | Location | Before | After | Why |
| --- | --- | --- | --- | --- |
| MEDIUM | WorkspaceView / AppStyle | 品牌标记只在侧栏底部出现，路由图标与文字层次接近 | 顶部品牌区、统一图标底座、选中图标实色、底部真实仓库状态与分支 | 用品牌和状态层级建立工作区辨识度，保留原生 List 选择与键盘导航 |
| MEDIUM | Components / PanelHeader | 面板标题只有单个图标 | 共用 28 pt 图标底座、标题字重与稳定间距 | 页面标题与侧栏、Sheet 形成一致的组件体系 |
| MEDIUM | ChangesView / Components | 暂存准备状态主要依靠提交按钮文字，输入表面与其它字段不同 | 已暂存计数、统一输入表面与焦点边框、原生主按钮、准备状态结构线 | 看清实际提交范围，保持原生编辑、危险操作和提交权限判断 |
| MEDIUM | HistoryTableView | 引用名称串接为一段文字，提交图使用直线折角 | 引用标签、短 SHA 底座、平滑分支连接线；完整引用仍在提示与辅助访问名称中 | 提高扫描速度与分支拓扑的辨识度，不增加读取或修改历史 |
| LOW | EmptyPanel / AppStyle | 通用色块图标 | 带连接线与节点的分支图形，中心保留语义图标 | 空状态与品牌/提交图一致，装饰不进入辅助访问树 |
| LOW | WelcomeView | 页脚纯文字流程标签 | 同一套圆角流程标签，保留“浏览—暂存—提交”顺序 | 欢迎页与工作区使用同一视觉语言 |

原生分栏、Inspector 崩溃修复、Git 领域服务、操作队列、原始 Diff 与复制边界保持原有实现。没有新增 UI 或动效依赖。

提交编辑器沿用 macOS 原生字段：`⌥↩` 换行、`⌘↩` 提交。普通回车结束字段编辑；提示已写入占位文字、帮助和准备状态。原生输入及快捷键不添加自定义等待动画。

## 动效与可访问性

最近仓库行扩展至工作区侧栏，悬停仅 120 ms 背景反馈；既有欢迎标记 280 ms、操作反馈 160 ms 和实际刷新旋转保留。导航、文件选择、代码行和主题切换继续即时响应。应用动效开关和系统减少动态效果约束保持有效。

新增图形隐藏于辅助访问树。暂存计数提供明确名称及标识，提交消息保留原生字段角色与 `commit-message` 标识。引用显示最多两个标签及剩余计数，完整名称保留在帮助和辅助访问文本中；空引用不读出无意义的“引用”。

主要 Token 的静态色对均达到 4.5:1，见 [color-pairs.json](color-pairs.json)。这不代替实际材质、所有控件状态、VoiceOver 或自动辅助访问审查。

## 实际验证

采用私有 Git 仓库、UITests 偏好域、内存数据库及唯一窗口状态名称。仓库包含真实提交与分叉/合并，用于检查历史图和引用；正常用户仓库不用于暂存或提交测试。

浅色检查已核对原生焦点、多行粘贴、`⌥↩` 实际逐键换行、草稿重启恢复、暂存计数 1 → 2 → 0，以及 `⌘↩` 真实提交。Git 核对了完整两段消息、两个提交文件和剩余改动，见 [keyboard-commit.json](keyboard-commit.json)。原生菜单的选中与执行分别确认，没有仅凭选中状态判断操作完成。

最终源码、浅深色/密度、最小窗口、Inspector 恢复、构建、核心与包的证据见 [validation.json](validation.json)。原生自动化模式初始化依旧阻塞，因此增强后的 InterfacePolishTests 只标记编译；手动行为检查与完整自动化验收分别记录。

Not verified：完整原生套件与 144 阅读组合、新源码 30 次 Release 性能、系统显示辅助选项实际切换、VoiceOver/完整键盘、慢速/逐帧动效审查。保留已有失败结果与各轮来源，V1.0 发布继续未完成。

本轮已检查视觉和手动行为范围的结论见 validation.json；完整自动化、性能及辅助技术不计入该范围。
