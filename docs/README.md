# WeGit 文档索引

WeGit 是面向 macOS 的原生 Git 客户端，以「查看改动 → 暂存 → 提交 → 同步」为核心工作流，采用 Swift、SwiftUI 和 Git CLI。

截至 2026-10-10，仓库已实现提交、历史、分支、同步、认证通道与设置等主要流程，正在完成原生 UI 和发布验收。以下设计文档仍描述完整目标；实际实现、测试证据和剩余工作以 [开发进度](DEVELOPMENT.md) 为准，不把计划等同于已完成。

## 版本与规范用语

- **文档修订版 v1.1**：本次整理后的文档版本；不等于产品 V1.1。
- **产品 V1.0 / P0**：首版必须完成的能力；后续版本列表属于路线规划。
- **必须 / 不得**：相应版本的验收约束。
- **建议 / 优先**：当前推荐方案，可在验证后调整并记录原因。
- **待验证 / 待决策**：尚未确认的假设，不应当作实现事实。
- PLAN 中未勾选的任务表示待完成；只有附有实现和验证证据时才能标记完成。

保留原有 **macOS 27+** 产品目标。实际 Deployment Target、Xcode/Swift 版本、SDK API 可用性和分发方式，须在 Phase 0 验证并记录，不能仅凭视觉参考图推定。

## 统一术语

正文以中文说明为主；首次出现可附英文名称。Git 命令、类型名、文件路径用行内代码，界面英文作为设计映射保留。

| 中文术语 | 英文或代码 | 使用约定 |
| --- | --- | --- |
| 仓库 | Repository | Git 仓库及其关联工作目录 |
| 工作区 | Working Tree | 当前检出的文件内容 |
| 暂存区 | Index / Staging Area | 下一次提交的内容 |
| 暂存 / 取消暂存 | Stage / Unstage | 在工作区与暂存区之间选择提交内容 |
| 丢弃改动 | Discard | 删除指定未提交改动，须说明恢复限制 |
| 提交 / 修改上次提交 | Commit / Amend | 创建提交 / 改写当前 HEAD 提交 |
| 差异视图 / 差异块 | Diff Viewer / Hunk | 文件差异 / 连续差异片段 |
| 提交图 | Commit Graph | 提交及父子关系的可视化 |
| 获取 / 拉取 / 推送 | Fetch / Pull / Push | 更新远端跟踪信息 / 整合远端改动 / 推送提交 |
| 储藏 | Stash | 临时保存未提交改动 |
| 上游分支 | Upstream | 当前本地分支配置的跟踪分支 |
| 分离 HEAD | Detached HEAD | HEAD 直接指向提交而非本地分支 |
| 未诞生分支 | Unborn Branch | 尚无首个提交，HEAD 尚不能解析为提交 |
| 检查器 | Inspector | 可选的辅助元数据面板，不等同于详情主栏 |

`C` 是 Git 的复制状态；冲突统一使用 `U` 和「冲突」文本。工作区是否干净与分支是否已推送是两个独立状态。

## 维护约定

1. 保留现有文件名，通过相对链接相互引用。
2. 每份文档只使用一个一级标题，章节从二级标题开始。
3. 列表描述并列事项，表格用于范围和状态对照，代码块只用于代码、命令或结构示意。
4. 范围变化先更新 PRD，再同步页面、服务和开发计划。
5. 实现完成后补充验证结果；设计目标与实际结果分别记录。
6. 新增文档时更新本索引；不要创建同一内容的多份副本。
