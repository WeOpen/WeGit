# 更新记录与清理

本文描述 v2.0 开发候选的更新记录功能。版本实际验收状态见 [实施进度](V2_0_PROGRESS.md)；当前尚未配置生产更新公钥和签名清单，不表示自动更新已经可用于公开发行。

从应用菜单打开“检查更新…”，选择“更新记录”。列表显示当前安装位置附近保留的更新事务，包括版本、状态、时间和已知占用。读取列表不会安装、回退或重放未完成事务。

| 状态 | 可进行的操作 |
| --- | --- |
| 已完成 | 文件和来源仍可验证、没有未完成的数据恢复义务时，可预览并确认清理 |
| 已回退 | 原目标已恢复且数据恢复义务已结束时，可清理 |
| 已中止 | 有有效中止记录且原安装目标未变化时，可清理 |
| 准备未完成 | 只有完整匹配已登记范围的自有文件可清理；未完整复制或已变化的内容继续保留 |
| 等待安装、等待重开、正在使用 | 保留记录，不提供清理 |
| 未验证、需要核对 | 可定位原目录并导出诊断；不删除无法确认的文件 |

“清理…”先读取具体计划，显示版本和占用。取消不删除文件。确认后再次核对来源、目录身份、文件摘要与事务状态，只清理该记录拥有的文件，不删除当前应用、原数据库或目录外的内容。清理不可撤销；需要保留的旧包和数据应先另行备份。

清理中断会保留进度。重新打开记录页、刷新并再次选择“清理…”后，应用重新核对剩余范围；它不会自动继续删除。如果文件已经变化或出现未登记内容，停止清理并保留现状。旧版遗留的无所有权证据目录可能只能定位核对，不能保证所有中断都可由客户端清除。

“导出诊断…”仅保存状态、版本、时间、占用和原因代码。文件不含本地路径、授权 token、偏好、数据库或私钥，也不是可恢复数据的备份。设置中的“查看原始数据备份”对应首次 v1→v2 数据迁移，与更新记录的诊断导出用途不同。

保留上限仍为 20 项、总计 1GiB。未知、损坏或无法计量的记录不会被忽略以腾出容量；它们会阻止新的更新准备。没有可信公钥时可以查看“未验证”状态，但不能据此安装或清理未经验证的记录。安装器恢复执行、生产安装和最终性能仍按 [v2.0 契约](V2_0_CONTRACTS.md)分别验收。
