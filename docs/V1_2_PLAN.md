# WeGit v1.2 开发需求

更新：2026-10-24。本轮交付是需求整理，跟踪任务 [#55](https://github.com/WeOpen/WeGit/issues/55)。本文件汇总原有 v1.2 规划和 v1.1 后移项，给出推荐顺序、最小范围及验收标准；优先级是开发建议，具体交付范围与日期在拆分功能 Issue 时确定。

## 发布安排（2026-10-26）

用户确认将1.1.1的界面、交互和R5品牌资源合入主线，随1.2一并发布，不单独发布1.1.1。本次只集成代码和资源，不创建版本标签或Release。完整原生回归、有效性能采样和既有发布门禁仍需针对1.2最终源码验收。

## 1. 目标、基线与成功标准

目标是让用户在应用内精确组织提交、移植或撤销修复、追查每行来源，并可靠地使用多个 Git 工作区。优先解决已有明确缺口，再增加复杂编辑能力。当前没有真实 Beta 使用频次统计，优先级依据是现有功能、依赖和数据风险。

- v1.1 四项必选 Stash、Remote、Tag、文件历史与定向搜索已经实现。固定应用源码 `835b8c4` 的完整原生功能回归 54/54、0 失败、0 跳过，阅读矩阵 144 张；[Beta 记录](acceptance/2026-10-24/v1-1-beta/README.md)保留其来源和限制。
- 已有文件/差异块暂存、普通提交、Merge、Pull Rebase、外部冲突编辑、Merge/Rebase 继续与中止，作为回归基线，不重复建设。
- 当前代码明确拒绝打开 linked worktree；能检测分支被其他 worktree 占用，并不等于支持打开或管理它。
- Cherry-pick/Revert 目前只有外部序列状态识别，应用内继续/中止仍仅支持 Merge/Rebase；从 v1.1 后移到本需求池。
- 本轮另提交太极 Loading 动效，由 [#54](https://github.com/WeOpen/WeGit/issues/54) 跟踪。它改变应用输入；旧 Beta 的 54/54 与性能结果只适用于旧源码，新应用仍需按实际范围验收。

每项需求完成时，用户可从应用入口完成正常操作、取消、失败核对和冲突恢复；外部 Terminal 修改或重开应用后状态仍准确；写入范围、实际 Git 状态、源码与验收证据均可核对。功能实现、托管验证和版本发布分别记录。

## 3. 各项开发边界与验收

### V12-01 · Worktree

- 第一步支持打开、最近/收藏、切换与重开已有 linked worktree；仓库身份、文件、草稿、页面、HEAD、index 与序列状态按各自工作区隔离。
- 区分每个 worktree 的 Git 目录和共享 common directory。共同引用、Remote、Tag、Stash、Fetch 与配置写入需协调，不能只删除当前打开保护。支持实际 Git 配置来源，包括启用 `extensions.worktreeConfig` 的情况。
- 共享目录事件应刷新受影响工作区；工作区内文件事件只刷新对应工作区。避免为同一共享目录建立重复扫描或持续 Status 轮询。
- 第二步提供列表、路径/分支状态、创建与安全移除。已被使用的分支、脏内容、锁定 worktree、嵌套路径和过期登记均需明确处理；首版不提供强制清理用户 worktree。
- 验收使用主仓库和两个私有 linked worktree，覆盖不同分支/Detached HEAD、独立草稿/暂存、共享 Tag/Remote 外部修改、并发写入、路径替换、移除后重开与中文/换行路径。不得借测试清理本项目实际 worktree。

### V12-02 · Cherry-pick / Revert

- 从历史选择一个普通提交，展示当前分支、当前 HEAD、目标 SHA 与将改变的文件。Merge 提交的 mainline 选择及多提交队列另行设计。
- 执行要求工作区/暂存区干净且无其他序列操作；不自动 Stash，不隐式改写远端历史。执行前重验仓库身份、HEAD/分支与目标对象。
- 冲突后可外部编辑、标记解决、继续或中止；关闭/重开应用仍识别真实 Git 序列。Revert 用新提交撤销，不作为 Reset 的替代名称。
- Hooks、签名失败、空变更、外部取消和不确定回执各有真实结果；先核对 HEAD/序列状态，再决定后续操作，不自动重复写入。
- 验收正常单提交、冲突继续、冲突中止、重开、空提交、目标变化和签名/Hooks 失败，核对 HEAD、索引、工作文件、草稿及原提交保留。

### V12-03 · Blame

- 从文件历史或已提交文件进入逐行归属，显示作者、提交、时间，点击行可打开对应提交和该文件的历史。
- 首版基于明确提交与该时点的路径；未提交文件内容须单独标识或明确限制，不能把工作区行号直接套到 HEAD。说明 Git 对重命名、复制与 Merge 的检测边界。
- 对大文件使用有界读取、分页或按可见范围获取；后台查询可取消，快速切仓库/文件/提交时旧结果不能覆盖新结果。
- 验收多作者、重命名、根提交、删除文件历史、空/二进制文件、中文/换行路径、大文件与连续切换；所有操作保持 HEAD/index/工作文件不变。

### V12-04 · 选中行暂存 / 取消暂存

- 沿用现有 Unified/Split 阅读器和选择系统，按当前暂存层提供正确动作；预览只包含实际将写入索引的选择范围。
- 从原始补丁和字节构造操作，不能从高亮文本、换行后的显示行或忽略空白后的差异重建补丁。替换行及相邻增删行必须有确定的选择语义。
- 写入前重验 HEAD、索引和工作区快照；仅修改选中范围，保留其他已暂存/未暂存内容和工作文件。无法可靠表示的文件继续提供已有文件级操作。
- 验收新增/删除/替换、多 hunk、零上下文、CRLF、无末尾换行、Unicode、未诞生分支、外部编辑和陈旧选择；通过索引 blob 与原始工作文件字节验证范围，而不是只比较变更数量。
- 选中行丢弃另属候选，涉及工作文件写入和恢复边界。

### V12-05 · 内置冲突编辑器

- 从冲突文件进入，固定 BASE、OURS、THEIRS 的对象及来源，RESULT 可按块接受和手动编辑。Rebase 等操作下标签显示实际来源，不把 OURS 恒定解释成用户分支。
- 提供未处理块导航、原始内容比较、取消和明确保存。保存重验文件/索引状态并原子写入；“保存结果”与“标记已解决”分别有可核对结果。
- 首版聚焦文本内容冲突；add/delete、rename/rename、二进制、符号链接、Submodule gitlink 和自定义 Merge Driver 先定义支持边界，并保留外部工具路径。
- 验收 Merge、Rebase、Cherry-pick/Revert 文本冲突，Accept Both、手工修改、CRLF/编码/末尾换行、外部编辑、保存失败与重开草稿；接受一侧不等同于业务逻辑正确。

### V12-06 · 独立 Rebase

- 已有 Pull Rebase 继续保留；新增的是从分支页显式选择目标并启动 Rebase，预览起点、目标和待重放提交。
- 首版要求无其他序列且工作区干净；对已发布提交说明历史改写，保留后续同步的显式 Lease 确认。
- 普通执行、重复冲突、继续/中止、重开和 Hooks/签名失败复用经过验证的序列恢复能力。外部序列来源不明时提供受限操作。
- 验收分叉、已包含提交、无工作、冲突继续/中止、目标移动、外部操作和最终分支/HEAD/索引；中止前说明哪些操作中改动会撤回。

### V12-07 · Interactive Rebase

- 选择明确边界内的提交，支持 pick/reword/edit/squash/fixup/drop 和排序；预览原 SHA、顺序与动作，不混用格式化消息或可变分支名作为身份。
- 首版仅普通线性提交序列；Merge 重放、任意命令执行和多分支批量操作另行设计。提交边界、todo 与恢复回执在执行前固定并重验。
- 消息编辑取消、edit 停点、冲突、空变更、Hooks/签名失败、重开、继续和中止形成完整闭环；不以退出编辑器成功等同 Rebase 成功。
- 验收所有动作及组合、重复冲突、External Terminal 修改 todo/HEAD、发布分支和取消；保存旧提交定位信息，说明恢复限制。

### V12-08 · Submodule

- 显示已配置模块的路径、父仓库记录 OID、实际子仓库 HEAD、初始化及脏状态；从父仓库显式打开子仓库。
- 初始化/更新针对确认的记录提交，预览路径及可能的下载；不默认追随远端最新提交，不递归覆盖脏内容。父仓库 gitlink 的暂存与子仓库内部文件操作分开。
- 缺工具、认证取消、离线、未初始化、URL 变化、嵌套模块与特殊路径有受限结果；复用已有凭据和主机验证，不保存私钥。
- 验收私有父/子仓库与本地 bare remote，覆盖记录与实际 OID 不一致、子仓库脏状态、更新失败/取消及外部变更；两级仓库草稿和写入目标保持独立。

### V12-09 · LFS

- 检测所选 Git 环境中的 Git LFS 能力与配置来源，区分普通文件、有效指针、已有内容和缺失对象；工具缺失时给出可操作结果。
- 首版以状态和阅读边界为主。获取内容须由用户明确触发并能取消，记录网络结果；不自动安装工具，不因为打开 Diff 就下载整仓库对象。
- 解码图片和预览大对象前检查类型、声明大小、实际大小与读取上限；沿用二进制摘要和外部打开路径。
- 验收无工具、正确/损坏指针、对象缺失、离线、获取取消及失败后状态。真实 LFS 服务验证与本地指针夹具分别记录。

## 4. 推荐开发顺序

| 批次 | 工作 | 退出条件 |
| --- | --- | --- |
| M0 | 固定新代码基线，继续 v1.1 性能和交付跟进 | 新源码回执明确，既有未完成验证保留；不借版本变更关闭 #35 |
| M1 | 已有 Worktree 可靠打开、Cherry-pick/Revert、Blame | 多工作区身份正确；单提交恢复闭环；只读追踪不改仓库 |
| M2 | 选中行暂存、Worktree 列表/创建/安全移除、独立 Rebase | 原始补丁范围正确；共享写入协调和序列恢复通过 |
| M3 | 三方冲突编辑器、Interactive Rebase | 文本保存、序列编辑、冲突、重开和中止均可核对 |
| M4 | Submodule、LFS 状态 | 嵌套写入、工具和网络边界通过各自夹具与实测 |
| M5 | 选定实际范围的 Beta、性能、安装与发布验收 | 同一源码/制品可追溯，实际发布门禁与反馈完成 |

首次开发 Issue 建议从 Worktree 的“可靠打开已有工作区”开始，先解决当前明确拒绝该布局的问题。共享目录、队列和监视验证完成后，再开放创建/移除。不要把第一步塞入一个覆盖全部管理能力的大 PR。

| 选中行丢弃、更多批量操作 | 独立正确性验收 | 精确工作文件写入、外部变化、取消和恢复限制 |

## 6. 性能、验证与发布要求

- 新功能沿用 WeGitCore、参数数组、字面路径、目标重验、串行写入、快照刷新和草稿恢复。共享引用与独立工作区需要不同协调范围，实施前先验证锁顺序与身份规则。
- 所有写入测试使用私有临时仓库和本地 bare remote，隔离 global/system Git 配置和私有签名服务。实际用户仓库、worktree、凭据及系统保护状态保持原样。
- 本地不执行 XCTest；可运行独立检查和编译测试目标。托管原生用例先通过实际 smoke，再验收精确范围，并保留源码回执、日志、xcresult、截图和测试计数。
- 普通 Release p95 保留既有预算：外壳 500 ms、Status 300 ms、Diff 150 ms、历史首屏 300 ms、稳定外部更新 1000 ms、启动 1000 ms。普通夹具至少 30 次；大型仓库单独记录规模、RSS、取消响应和压力条件。
- 新读入口先固定夹具、首次查询及稳态预算，再记录原始样本；现有新功能后台 2000 ms p95 是参考边界，不用缓存后的页读取替代首次路径/对象准备。
- 多工作区避免重复监视和整仓库扫描；Blame、三方文本、图片与 LFS 均需有界读取与显示，工作留在后台，取消后的旧结果不能覆盖新上下文。Loading 隐藏、场景非活动或减少动态效果时不持续刷新。
- 滚动用有效帧率/卡顿、固定轨迹和内存测量验证；30 次全部为 0 的帧指标不能证明流畅。启动缺少有效样本时保持未通过，不填造或删选样本。
- 新入口保留原生键盘、焦点、辅助访问名称、浅深色和窄窗口行为，布局少用重复的次级说明。完整辅助功能验收按此前暂缓决定保留实际状态。
- v1.1 的性能、受保护 Mac 安装/迁移/回退、真实 Beta 反馈、部分认证兼容性和专用 Full acceptance 仍是质量跟进。它们可限制发布，不作为“新增 v1.2 功能”计数，也不随新版本自动关闭。
- 版本发布仍要求同一源码与制品、实际性能开销和既有门禁；v1.0 的一次性发布例外不自动延续。未固定设备、人员投入及反馈周期，因此没有日历日期承诺。
