# 标签管理

侧栏「标签」或 ⌘5 打开列表。名称搜索按字面匹配，支持中文和带 `/` 的名称；可继续加载。选择标签后查看准确目标提交、附注及文件差异。Merge 目标可选择比较父提交，二进制与大型差异沿用现有阅读器。

「创建标签」使用当前 HEAD；历史提交的「操作 → 从此提交创建标签」使用所选完整 SHA。支持轻量与附注标签，附注保留原文。沿用当前 Git 签名配置；`tag.gpgSign` 要求签名时使用附注标签。签名工具失败不会降级为未签名标签。保存失败保留表单，外部 HEAD、配置或同名引用变化需要重新确认。

「删除本地标签」确认名称与原始对象 ID，只删除该本地引用；工作区、分支与远端标签保持原状。外部移动标签后，旧确认不会删除新对象。符号标签仅供查看。

「推送标签」选择 Remote 与一个具体推送地址，核对完整引用和原始标签对象后执行。仅推送选定的一个标签，关闭隐式 `followTags` 与 mirror；不强制移动已有远端标签，也不提供远端删除。远端存在同名不同对象时停止，即使两个附注指向同一提交也不会覆盖。

推送取消、超时或回执丢失可能发生在远端已经写入之后。此时「核对远端」重新查询准确引用，对照原始标签对象给出存在、缺失或不同对象的结果；不会自动重试。该提示只在当前仓库会话内保存；重新打开后仍必须先查询远端再确认新推送。

后台查询可取消，按仓库历史刷新代数更新，不因每次工作区文本变化扫描标签。读取有字节上限；大量标签应输入名称缩小范围。标签名称与消息不拼接到 Shell 中，写入走现有串行队列和仓库身份校验。

行为依据：[Git Tag](https://git-scm.com/docs/git-tag)、[Git update-ref](https://git-scm.com/docs/git-update-ref)、[Git Push](https://git-scm.com/docs/git-push)。验收范围见 [本轮记录](acceptance/2026-10-23/tag-management/README.md)。
