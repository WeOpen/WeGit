# WeGit 本地 Git 完整版收口建议

原建议：2026-10-29；状态更新：2026-11-03。用户希望集中完成基础能力，先交付一个完整版本，后续大版本专注有意思的功能。本文件从旧 WIP 中保留原 C01～C10 规划，供后续选择范围。V12-01～V12-09 已完成开发集成和固定源码回归，见 [v1.2 执行记录](../plans/V1_2_EXECUTION.md)与[最终开发证据](acceptance/2026-11-03/v1-2-final/README.md)。本轮仅授权提取有价值内容及清理旧分支，不启动下列十项候选实施。

## 1. 目标、约束与完成定义

下一次公开交付集中完成通用本地 Git 工作流：组织改动、整理历史、比较与移植修复、切换任务、处理冲突，以及找回可恢复的提交。涉及写入的流程同时交付预览、取消、失败核对和重开恢复。

- v1.2 开发里程碑已收口；未来完整稳定版选取哪些补齐项，需单独确定范围。版本号在制品收口时确定，本文不修改应用版本或创建 Release。
- 内部按依赖拆分 Issue/PR，继续经过必需检查和集成；面向用户集中交付。产品范围固定后，只加入阻塞缺陷修复，其他新想法进入后续需求池。
- 保持 macOS 27+、Apple Silicon、Git 2.46+ 和原生工作台定位。通过 GitHub Releases 与项目网站分发；Developer ID/公证沿用既有可选安排。
- 常用操作复用 Changes、History、Branches、文件菜单、命令面板和 Settings。高级动作按上下文展开，减少重复标签和说明。
- “完整”以真实工作流和恢复边界判断。已实现、专项通过、最终版本验收、公开发布分别记录。

## 3. v1.2 之后集中补齐的范围

原建议将以下十项作为集中交付候选。实际范围尚待确定；若选取这些模块，可先定义 C01/C02/C03 的数据契约与 C10 的更新信任方案，再推进其余界面和便捷能力。质量工作随所选项实施，在最终源码集中验收。

| 编号 | 模块 | 新增范围 | 完成标准 |
| --- | --- | --- | --- |
| C01 | Reset 与 Reflog 恢复 | Soft/Mixed/Hard Reset、撤回最近本地提交、浏览 HEAD/分支 Reflog、从旧提交恢复分支 | 展示 HEAD/index/工作文件的实际影响；写入前固定目标；保留恢复定位信息并检查对象是否仍存在 |
| C02 | 任意比较与补丁 | 两个提交/分支/Tag 比较、按共同祖先查看分支改动、标准文本补丁导出与应用预览 | 明确两点比较和共同祖先比较的基准；固定对象后分页读取；导出匹配原始差异，应用只写入已确认范围 |
| C03 | 文件处理闭环 | 选中行丢弃、从历史版本恢复单文件、未跟踪文件的忽略规则入口 | 默认只修改工作文件，保留未选内容与索引；覆盖前准备可核对备份；精确预览 `.gitignore` 规则影响 |
| C04 | 多提交操作 | 有序 Cherry-pick/Revert 队列、Merge 提交的 mainline 选择 | 固定提交顺序与父提交选择；重复冲突、空变更、Hooks/签名失败和重开时仍可核对、继续或中止 |
| C05 | 临时任务与消息 | 从 Stash 创建分支、显式保存后切换任务、按仓库保存可复用提交消息历史 | Stash 对象与目标重新核对；应用失败保留记录和草稿；消息去重、可清空且不会覆盖当前输入 |
| C06 | 图片差异 | PNG/JPEG/WebP 前后对照、缩放和平移 | 使用明确两侧对象；控制压缩文件与解码像素预算；大图显式加载、可取消，未发现 LFS 内容时沿用受控获取 |
| C07 | 签名设置与兼容性 | 仓库级 GPG/SSH 签名开关、已有密钥标识选择、有效配置来源和签名结果 | 复用现有工具与密钥存储；真实交互失败可解释、草稿保留；签名失败不静默降级或跳过 Hooks |
| C08 | 多任务与键盘效率 | 多窗口、快捷键自定义、统一查询入口扩展到 Tag/Stash/已跟踪路径 | 每窗口选择/页面独立，同一工作区草稿有明确归属；共享写队列保持一致；快捷键检查冲突并保留原生编辑操作；搜索有界、可取消 |
| C09 | 仓库扩展的常用配置 | Submodule 添加/移除及来源变更；LFS track/untrack 规则编辑，固定对象获取沿用已集成能力 | 固定嵌套仓库和配置身份；保护脏内容及 `.gitmodules`/`.gitattributes` 原文；默认不重写历史或整仓库下载 |
| C10 | 更新与数据迁移 | 检查更新、版本说明、可信下载与校验、退出后安装、失败回退、偏好/草稿迁移与备份恢复 | 草稿版本不进入稳定更新；发布元数据和制品有独立可验证签名；安装前核对当前包与活动任务；更新失败仍可启动旧版并恢复数据 |

### 正确性边界

- Reflog 恢复依赖 Git 对象仍存在；未提交内容需要独立备份。Hard Reset 和丢弃不能统一承诺“撤销即可找回”。
- C02 首批补丁应用支持普通文本 diff，执行前重验路径、文件字节、索引和目标。邮件补丁的提交序列需另行定义，不能把“应用文件变化”报告为“已创建提交”。
- C03 行选择基于原始字节，继承 V12-04 的换行、替换行和陈旧选择保护。忽略规则不自动移除已跟踪文件。
- C04 的多提交计划与 C05 的 Stash 切换都要识别部分成功；取消或回执丢失后先核对 Git 状态，避免重复写入。
- C07 首批以当前仓库作用域为默认；继承/include/worktreeConfig 来源需保留。全局设置只在用户明确选择该作用域后编辑，验收仍使用隔离配置。
- C08 多窗口共享同一工作区时，不能各自创建互不协调的写队列或全量扫描；共享引用和工作区局部状态沿用既有分层协调。
- C09 Submodule 移除必须保护未提交/忽略内容和独立提交；LFS 规则变更与历史迁移分别设计。Sparse Checkout、LFS 历史迁移、Bare 仓库写管理另行排期。
- C10 先固定发布签名、更新源、密钥轮换和安装恢复契约。SHA-256 用于字节一致性，独立签名用于来源认证；ad-hoc 签名沿用准确的系统信任说明。

## 5. 完整稳定版的验收

历史 [#3 辅助功能](https://github.com/WeOpen/WeGit/issues/3)、[#4 性能](https://github.com/WeOpen/WeGit/issues/4)、[#5 兼容性](https://github.com/WeOpen/WeGit/issues/5)、[#6 专用验收](https://github.com/WeOpen/WeGit/issues/6)、[#7 安装迁移](https://github.com/WeOpen/WeGit/issues/7)、[#9 真实反馈](https://github.com/WeOpen/WeGit/issues/9)已按维护者明确延期使用 not_planned 归档，#35/#57 的正式M5部分沿用该决定。原未通过条件保留；关闭Issue不构成正式发布签核。v1.1 Beta 的实际界面性能曾超预算，不能用当前Core专项样本替代整版Release UI/Instruments验收。

| 普通 Release 指标 | 已有 p95 预算 |
| --- | ---: |
| 工作台外壳可用 | < 500 ms |
| Status 首屏 | < 300 ms |
| Diff 首屏 | < 150 ms |
| History 首屏 | < 300 ms |
| 稳定外部事件到可见更新 | < 1000 ms |
| 启动可响应 | < 1000 ms |

- 固定源码、夹具、设备和缓存条件，每项至少 30 个有效样本。新入口先定义规模、首次查询/执行、内存与取消预算，再实测；缓存页读取不能替代首次路径建立。
- 大型历史、复杂提交图、磁盘 Diff、图片、多个 Worktree/窗口和 LFS 分别记录 RSS、滚动卡顿与取消响应。后台读取和隐藏动画不得增加持续全仓库扫描或逐帧 Git 工作。
- 每项写入覆盖正常、取消、失败、外部 Terminal 修改、切仓库和重开；通过 HEAD、索引 blob、工作文件字节和恢复记录核对结果。
- 新入口随功能检查键盘、焦点、最小窗口、中英文浅深色和基本辅助访问名称。完整 VoiceOver/系统辅助访问审查沿用此前暂缓决定，保留真实待验状态。
- 本机不执行 XCTest。独立检查和测试目标编译可运行；托管先取得 smoke 实际 1/1、0 失败/跳过，再运行明确专项，并保留固定源码、xcresult、截图、日志与计数。
- 最终源码重新执行完整核心/原生回归和有效性能采样。测试包、普通 Release 包和实际下载包分别核对来源，正式制品排除 XCTest 权限。
- 在干净、受保护的目标 Mac 实际执行 HTTPS 下载、安装、首次启动、仓库读写、更新、迁移和回退。设备限制和真实反馈保持独立记录；旧版本的一次性发布例外不自动延续。

## 6. 后续大版本的方向

完整稳定版之后，基础缺陷、性能和兼容性继续通过维护版本处理；大版本按一个可感知的新工作流组织。

| 方向 | 有价值的新体验 |
| --- | --- |
| GitHub/GitLab 协作 | PR/MR 列表、检出审阅、评论、Review、CI 状态与发布前核对；账户权限独立管理 |
| 可选 AI | 解释差异和历史、辅助拆分提交、生成提交消息建议、定位变更风险；发送范围可确认，本地 Git 流程保持独立 |
| 图形化回归定位 | Guided Bisect、候选提交对照、可重复的定位过程与结果记录 |
| Worktree 任务工作流 | 为并行任务创建/恢复工作区、比较任务结果、快速审阅和清理；建立在已验收的基础管理上 |

每个方向先验证实际场景，再确定版本范围。基础收口阶段不提前建设完整 IDE、任意命令插件平台、云端托管或团队管理后台。
