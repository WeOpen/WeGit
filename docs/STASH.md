# 暂存记录（Stash）

v1.1 开发功能；未包含在已发布的 1.0.0 下载包中。实现与验证由 [#36](https://github.com/WeOpen/WeGit/issues/36) 跟踪，[验证记录](acceptance/2026-10-22/stash-management/README.md)区分已执行检查与待验范围。

从侧栏“暂存记录”或“工作区 → 暂存记录”（⌘4）进入。保存前可命名并查看将保存的文件；默认不包含未跟踪文件，勾选后才保存它们。忽略文件不保存。保存会清理所选范围内的改动，不自动切换分支。

选中记录后可分别查看“原未暂存内容”“原暂存区内容”和包含时的“未跟踪内容”。文件与差异沿用已有只读阅读器。列表显示消息、来源分支（Git 消息中可识别时）、日期与对象摘要，超过 200 条可逐批载入，最多 10,000 条。

- **应用**：恢复内容并保留原记录。
- **取出**：确认后恢复内容，成功才删除该记录；发生冲突时保留记录。
- **删除**：确认消息与对象后只删除该条，不修改工作区文件；没有一键清空。
- **恢复原暂存状态**：默认开启；关闭时不要求还原原先已暂存/未暂存的分层。恢复前需先提交或保存已跟踪文件的现有改动，并完成进行中的 Git 操作。

冲突时转到“更改”，用现有外部编辑与标记解决流程处理，再正常提交。Stash 冲突没有 `merge --abort`，界面不会提供虚假的合并中止操作。命令超时或列表并发变化时，先刷新核对工作区和记录，尤其当提示内容已应用时不要重复恢复。

Terminal 增删记录后，监听会刷新列表；也可用仓库刷新命令手动核对。确认时固定原对象与列表快照，旧编号失效时拒绝操作。如果编号在删除命令内发生竞争，核对实际移除对象并重新保存误移除的记录，提示刷新；这可能改变其列表位置和消息。

当前保守拒绝含子模块或特殊索引标记的 Stash 写操作，以及可能覆盖目录、未跟踪替代文件、忽略内容或符号链接父路径的操作。先在外部处理这些状态后再试。保护是执行前检查与执行后核对，无法阻止外部 Git/编辑器在任意时刻并发写入仓库；并发或不确定结果必须人工核对。此功能不扩大 linked worktree、bare 仓库等原有支持范围。
