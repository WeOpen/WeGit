# 文件历史与定向搜索

在改动文件或提交中的文件上右键选择「查看文件历史」。也可从「提交历史 → 文件历史」手动输入仓库相对路径，查询当前已删除的文件。历史文件入口从所选提交开始，其他入口从当前 HEAD 开始；底部显示固定起点。刷新重新读取起点，分页不会因外部 HEAD 移动而重复或遗漏记录。

改动列表中的未提交重命名使用 Git 状态记录的旧路径查询 HEAD 中的历史；编辑、Finder 和复制路径操作仍指向当前文件。复制记录不自动追踪其来源。

输入作者/邮箱、消息或提交时间范围可叠加筛选。搜索按字面而非正则表达式匹配；时间使用提交者时间，界面的日期范围包含首尾两天。查询延迟 250 ms 合并连续输入，切换条件会取消旧请求，关闭面板释放读取和 Diff 缓存。失败可以重试，取消不会被描述为没有历史。

默认跟随 Git 检测到的单文件重命名；关闭「跟随重命名」只查询当前路径。列表保留每次提交时的实际文件名，选择记录后用当时的旧/新路径读取 Diff。Merge 比较真实第一父提交，同时历史中保留 Git 遍历到的分支修改；根提交相对空树。删除、二进制和大文件沿用现有差异状态与明确加载限制。

重命名基于 Git 的相似度检测，不保证非线性历史中的任意移动，也不追踪跨文件复制。不能把目录当成单文件查询。文件名中的中文、空格、换行和 pathspec 字符原样保留；没有 Shell 字符串拼接。

首次查询建立只读的路径元数据快照，限制 8 MiB / 100000 条；随后按最多 200 个对象逐页读取完整提交。之所以不直接使用 `--follow --skip` 或在跟随时过滤，是因为它们可能跳过推进旧文件名所需的重命名记录。超过上限明确停止，可从较近的历史提交进入，而不会静默展示不完整结果。

依据：[Git Log 的跟随、过滤和 Merge 行为](https://git-scm.com/docs/git-log)、[Git Diff Tree](https://git-scm.com/docs/git-diff-tree)。[本轮验收与性能](acceptance/2026-10-23/file-history/README.md)。
