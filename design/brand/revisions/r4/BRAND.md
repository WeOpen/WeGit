## 1. 项目概述与品牌定位

### 1.1 产品背景

**WeGit** 是一款面向 macOS 平台的原生 Git 客户端。产品视觉应首先体现 Git 开发工具应有的**清晰、可靠、专业和高效**，其次通过适量、真实的中国传统文化元素形成独特记忆点。

本规范专注于 **Logo 与应用图标的视觉识别**，并为 GitHub、官网及后续品牌物料提供统一设计基础；不要求将整个应用的交互界面改造成“古风”风格。

### 1.2 核心理念

> **以 Git 分支为形，以朱砂方印为记。**
> 技术为主体，文化为点睛；极简而不单调，传统而不复古。

建议的设计表达：

- **Git 分支：** 体现分支、合并、历史与协作，是品牌第一视觉焦点。
- **「庫」字方印：** 表达仓库、保存、积累和可信记录，是唯一的中国传统文化元素。
- **现代几何与留白：** 保持原生 macOS 产品的精确、克制和可读性。

### 1.3 品牌关键词

`简洁` · `可靠` · `专注` · `精确` · `温润` · `东方气韵` · `macOS 原生`

### 1.4 非目标

- 不追求“传统文化元素大集合”。
- 不将太极、山水、书法笔触、祥云、青瓷等元素叠加到本次 Logo 内。
- 不使用繁复的印章纹样、金属浮雕、强烈纸张噪点和复古海报式装饰。
- 不为了装饰牺牲 Git 分支识别度、小尺寸可读性或系统兼容性。

## 2. 已锁定的设计决策

下列事项视为 **V1.0 固定约束**。除非明确启动版本变更，不在后续生成图片或绘制图标时擅自改变。

| 编号 | 事项 | 已确认结论 | 级别 |
|---|---|---|---|
| D-01 | 品牌核心 | Git 三节点分支 | 固定 |
| D-02 | 图形母版 | 完整 Logo 与 App Icon 使用同一个 Git 分支 SVG 路径 | 固定 |
| D-03 | 分支修正 | 删除历史版本左上 Logo 中多出的向下分支／游离尾笔 | 固定 |

## 3. 视觉系统的构成

### 3.1 三个品牌元素

| 元素 | 英文名称 | 功能 | 视觉优先级 |
|---|---|---|---|
| Git 分支及其红色主体 | Symbol | 产品识别、核心标志 | 1（最高） |
| `WeGit` 英文字标 | Wordmark | 品牌名称与专业气质 | 2 |
| 「庫」字小篆方印 | Seal / Signature | 东方文化识别、品牌落款 | 3 |

**核心逻辑：先识别 Git，再识别 WeGit，最后注意到「庫」印。**

### 3.2 两种主要标准组合

**A. 完整横向 Logo（Primary Horizontal Logo）**

```text
[红色 Git 主体（内部带白色「庫」方印）]  WeGit  [红色「庫」方印]
```

- 用于品牌页、官网页头、GitHub README Banner、介绍材料。
- 红色主体、内部方印、Git 分支结构与 App Icon 中的对应部分完全相同。
- 不将 App Icon 的奶白色外层底座直接搬入横向 Logo。

**B. macOS App Icon（Application Icon）**

```text
[奶白色底座 [红色 Git 主体 + 白色三节点分支 + 白色「庫」方印]]
```

- 用于 Dock、Launchpad、Finder、应用列表与相关系统展示。
- 无英文 `WeGit` 字标、无外部第二枚方印。
- 内部方印在适用尺寸下保留，作为红色主体的细节。

### 3.3 辅助组合

- **Symbol Only：** 红色 Git 主体 + 内部「庫」方印，供头像、方形品牌区域使用。
- **Wordmark Only：** 单独 `WeGit` 字标，用于视觉空间受限但需要显示品牌名称的场合。
- **Git Template Symbol：** 单色、无方印的 Git 分支辅助符号，用于工具栏、菜单栏等系统功能性位置。它不是新的品牌主 Logo。

## 4. Git 分支核心图形规范

### 4.1 唯一几何母版

**以此前确认的右侧 App Icon 中的 Git 分支形态为造型参考，按矢量方式重新描摹和校正。**

最终须满足：

1. **恰好三个空心圆环节点**，位于上、右、下三个方向。
2. 存在明确且可连续辨认的分支连接关系。
3. 删除历史左侧主 Logo 中多出的向下分支、尾巴或第四个视觉端点。
4. 全部路径终点、节点中心、线宽和圆角过渡采用固定坐标与参数。
5. 允许适当不对称，以保留 Git 分支的方向感，但绝不允许随机形变。
6. Logo 和 Icon 中的路径数据必须一致；**禁止仅凭肉眼绘制两份近似图形**。

### 4.2 建议几何初值

以红色主体宽高均为 `100u` 的设计坐标系为初步参考：

| 属性 | 建议起点 | 备注 |
|---|---:|---|
| 红色主体宽高 | `100u × 100u` | 基准坐标系 |
| 红色主体圆角 | 约 `17u` | 根据 macOS 预览再校准 |
| Git 路径主干线宽 | 约 `8–10u` | 以现有视觉参考为准 |
| 三个节点外径 | 约 `15–18u` | 三个节点保持统一 |
| Git 图形总高度 | 主体高度的约 `76%–82%` | 为印章及边缘保留空间 |
| 转折方式 | 平滑圆角 | 避免非预期的尖端、毛刺 |

> **重要：** 此表不定义节点最终的 `x/y` 坐标，也不授权改变现有三节点连线方式。应先复刻参考图，再在 SVG 中冻结具体坐标。

### 4.3 线条与节点

- 主干、分支尽可能使用一致的视觉线宽。
- 三个节点使用相同的外圆、内孔比例。
- 节点与连线相交时，交界处保持光洁，不出现白色重叠凸包。
- 线端、折角统一采用圆润的处理方式。
- 小尺寸显示时可以进行光学校正，但不能增减节点或改变分支拓扑。

### 4.4 母版一致性检查

应从 `git-symbol.svg` 派生各类标识，而不是：

- 单独生成一张大 Logo 图片；
- 再重新生成另一张“看起来很像”的 App Icon；
- 最后尝试人工对齐。

推荐实现：一个版本化的主 SVG 路径 + 颜色、缩放和容器的组合参数。

## 5. 繁体小篆「庫」印章规范

### 5.1 文字意义

「庫」与代码仓库（Repository）的语义相联系，强调存储、积累、版本历史和可信记录。它是本项目唯一明确采用的传统文化符号。

### 5.2 字形标准

- 必须是**繁体小篆的「庫」**，而非现代楷书、宋体、仿宋或未经核验的“篆书风格字体”。
- 参照可信的篆书字典或《说文解字》相关字形资料核对构形。
- 在尊重字形来源的前提下，对笔画粗细和印面疏密进行视觉修整。
- 最终**转为封闭、可编辑、可复用的矢量路径**，不依赖系统字体。
- **R3补充：** 小篆构形必须正确；印面排布需紧凑饱满，降低字与框的留白。边框不再采用完全笔直的CAD方框，而应有自然圆转、轻微边缘起伏与不均匀着墨。
- 绘制前需保存参考出处与字形考据记录，避免生成式图片出现错字、漏笔或杜撰笔画。

**注意：此前品牌效果图中出现的「庫」字只能作为位置与效果示意，不能直接认定已经符合小篆字形要求。**

### 5.3 印章外框

| 属性 | 最终要求 |
|---|---|
| 形状 | 近方印面，保持整体比例；边缘不强制CAD直线（R3修订） |
| 框线 | 单线方框 |
| 转角 | 以近直角或非常轻微的转角修饰为主，不做胶囊形圆角 |
| 文字 | 居中，四周留白均衡 |
| 装饰 | 无龙纹、云纹、破损效果、双层边框或多余文字 |
| 输出 | `seal-ku.svg` 为唯一字形和边框母版 |

### 5.4 双位置印章规则

#### A. 红色主体内部印章

- **位置：** 红色 Git 主体右下角。
- **配色：** 白色字形 + 白色单线方框，衬于红色主体。
- **初始尺寸：** 印章外框宽高约为红色主体宽度的 `16%–19%`，推荐先从 `17%` 测试。
- **边缘留白：** 印章至红色主体右边、下边的距离建议约为主体宽度的 `4%–5%`。
- **关系：** 不触碰 Git 分支线、节点或红色主体边缘；不能引入拥挤和错视。

#### B. 字标右侧外部印章

- **位置：** `WeGit` 英文字标右侧。
- **配色：** 朱砂红 `#B3322D` 字形与同色单线方框。
- **初始尺寸：** 方框高度约为字标大写字母高度的 `45%–50%`。
- **对齐：** 与字标建立明确的视觉基线关系，并保留独立间距。
- **权重：** 必须小于英文字标的整体视觉重量，不抢夺品牌名称的注意力。

### 5.5 两枚印章的相同与不同

| 项目 | 必须一致 | 允许变化 |
|---|---|---|
| 「庫」字笔画轮廓 | 是 | 否 |
| 单线正方形边框比例 | 是 | 否 |
| 字形在框内的位置与比例 | 是 | 否 |
| 整体尺寸 | 否 | 等比例缩放 |
| 颜色 | 否 | 内部白色、外部朱砂红 |
| 印章在版面中的位置 | 否 | 按各自组合规范布局 |

> 内外印章保持**同一字形的反色应用**，不分别改成两种不同笔画构成的印文样式。

## 6. 完整 Logo 组合规范

### 6.1 默认横版排列

```text
┌────────────────┐
│  Git Symbol    │   WeGit    [庫]
│ (内含小方印)   │
└────────────────┘
```

该示意只用于说明排列关系，**不是正式 Logo 源文件**。

### 6.2 元素间距

- 红色 Symbol 与 `WeGit` 字标之间保留稳定的基础间距。
- `WeGit` 字标与外部方印之间的间距应小于 Symbol 与 Wordmark 之间的间距，但不得视觉粘连。
- 整体尽可能沿共同视觉中线平衡；精确距离在最终 SVG 排版时冻结。
- 在宽屏版头中允许扩大外围留白，不允许拉伸任一品牌元素。

### 6.3 安全空间

建议设置统一保护区 `S`，初始可取红色主体宽度的 `20%`。组合 Logo 外侧至少保留 `S` 的空白，不与正文、按钮、其他 Logo、边框紧贴。该值需要在矢量定稿后复核。

### 6.4 可用组合

| 组合 | 推荐环境 | 备注 |
|---|---|---|
| 标准横版 | 官网、GitHub README、介绍页 | 首选 |
| 深色背景横版 | 深色主题网页、宣传材料 | 字标换为浅色；红色保持品牌基调 |
| Symbol 单独版 | GitHub 头像、社交头像 | 仍包含内部小方印 |
| Wordmark 单独版 | 狭窄位置 | 仅在已有足够品牌上下文时使用 |
| 单色功能符号 | Toolbar、Menu Bar | 仅辅助图标，不冒充完整 Logo |

### 6.5 禁止事项

- 不在横向 Logo 的红色主体外围额外增加奶白色 App Icon 底座。
- 不将外部印章随意改放到字标上方或嵌入字母内部。
- 不为适应某一张效果图而修改 Git 节点位置和连线。

## 7. macOS App Icon 规范

### 7.1 整体结构

已确定采用**奶白色底座 + 朱砂红主体 + 白色 Git 三节点 + 白色「庫」方印**的构成。

建议按照以下逻辑分层制作：

| 层级（下至上） | 内容 | 说明 |
|---|---|---|
| L1 | 米白底座 | `#F7F3ED`；作为图标承载背景 |
| L2 | 朱砂红主体 | `#B3322D`；极轻微印泥纹理 |
| L3 | Git 三节点图形 | 使用统一矢量母版的白色版本 |
| L4 | 小篆「庫」方印 | 右下角，白色单线方印 |

### 7.2 外层底座

- 保留温润、轻盈的奶白色质感，避免过黄或纸张陈旧感。
- 底座不能比红色主体更抢眼；其作用是提供清晰层次。
- 不使用厚重、偏移过大的投影及强烈高光。
- 应遵循目标 macOS 版本的当前官方图标形状、遮罩及分层要求；如采用 Icon Composer 工作流，应避免与系统圆角和光影重复叠加。

### 7.3 比例建议

| 属性 | 建议初值 | 验证方法 |
|---|---|---|
| 红色主体占底座宽度 | `79%–83%` | 对比 1024、256、64 px 展示效果 |
| 红色主体圆角 | 自身宽度约 `16%–19%` | 与整体底座层级协调 |
| 印泥纹理视觉强度 | 极低，约 `2%–3%` 不透明度为起始试验 | 1024 px 能隐约察觉；小尺寸不产生脏污感 |
| 小方印尺寸 | 红色主体宽度约 `17%` | 保证笔画可读、不抢主节点 |

以上比例属于**制作试验值**；最终以 1:1 系统预览为准。

### 7.4 不同主题的表现

- **默认／浅色环境：** 米白底座、朱砂红主体、白色分支与内部印章。
- **深色环境：** 保持核心红色、白色分支与字形；按系统预览微调外部底座的明暗与层次。
- **单色／着色环境：** 需要单独检查系统渲染与图标辨认度；必要时制作系统允许的图层适配版本，不改变品牌母版拓扑。

### 7.5 正式导出原则

- 设计源稿以矢量／可编辑图层为主。
- 主视觉从同一母版导出 `1024×1024` PNG 供预览和兼容用途。
- 为 Xcode 提供按目标 SDK 与 macOS 版本要求制作的资源目录或图标工程；不把演示海报截图作为正式 App Icon。
- 实际接入前，以所使用 Xcode 与 Apple 当前文档为准核实 `Icon Composer`、资源打包和外观支持细节。

## 8. 品牌色彩与质感

### 8.1 核心色板

| 颜色 | HEX | RGB | 主要用途 |
|---|---|---|---|
| **朱砂红（Seal Red）** | `#B3322D` | `179, 50, 45` | Symbol 背景、外部方印、有限的品牌强调 |
| **墨黑（Ink Black）** | `#1F1F1F` | `31, 31, 31` | 浅色背景下的 `WeGit` 字标、文本 |
| **宣纸米白（Paper Ivory）** | `#F7F3ED` | `247, 243, 237` | App Icon 底座、柔和品牌展示背景 |
| **纯白（White）** | `#FFFFFF` | `255, 255, 255` | 红色主体上的 Git 分支、内部方印 |

**原则：** 常规品牌 Logo 不再增加第二个高饱和品牌色，避免绿色、金色、紫色或蓝色进入核心图形。

### 8.2 印泥纹理

**R3/R4修订：以已确认生成图的自然印泥质感为准，缩小时不干扰识别。** 纹理应传达“温润的印泥表面”，而不是“旧印章破损”。

具体要求：

1. 仅用于朱砂红主体的大中尺寸展示。
2. 纹理分布均匀、对比微弱；避免明显斑驳、白色缺口和粗糙刮痕。
3. Git 分支与「庫」印章始终保持锐利、干净的实色边界。
4. 缩小到小尺寸后应近似纯色；必要时直接使用无纹理版本。
5. 优先保留纯色矢量底层，再用独立、可关闭的纹理图层叠加。

### 8.3 光影

- App Icon 可具有柔和的系统化层次与光影。
- 完整横向 Logo 以平面标识为主，不添加投影或浮雕。
- 不将明显纸张纹理铺满所有品牌背景。

## 9. 字体与排版规范

### 9.1 `WeGit` 英文字标

**方向已确定：偏古典、精致、克制的衬线字标。**

- 保留衬线字体带来的稳定、书卷气，避免厚重装饰字体。
- 调整 `W`、`e`、`G`、`i`、`t` 之间的字距，使重心自然。
- 字标最终必须转为矢量轮廓，固定字形与字距。
- 正式选型时需核对字体的商用授权；不得以效果图里无法确定来源的字体直接注册或交付。

**R4字标：** 从R3生成Logo直接提取轮廓，固定其字形与字距，不再使用R2候选字体重排，也不依赖系统字体。当前轮廓不冒称某一商业字体的原始授权母版。

### 9.2 产品 UI 字体

- macOS 应用实际界面优先遵循系统字体、动态字重与平台规范。
- 不将复古字体、小篆字体扩散用于菜单、表单、分支列表及功能按钮。
- 小篆仅用于品牌印章，不承担 UI 信息阅读任务。

### 9.3 宣传材料排版

- 中文说明文字选择现代、易读的字体。
- 保持充足留白、较明确的层级与适当行距。
- 不用装饰性中式边框、祥云、山水背景来“增加国风感”。

## 10. 不同尺寸、主题及使用场景

### 10.1 尺寸适配原则

主 App Icon 应保持统一识别结构。下表是**验证重点**，不是允许按尺寸任意修改品牌核心路径的指令。

| 检查尺寸 | 图形要求 | 印章策略 | 纹理策略 |
|---|---|---|---|
| 1024 × 1024 | 全部保留 | 内部方印完整 | 极轻微 |
| 512 × 512 | 全部保留 | 内部方印完整 | 极轻微 |
| 256 × 256 | 全部保留 | 内部方印完整 | 可进一步减弱 |
| 128 × 128 | 节点清晰 | 验证印文轮廓 | 近似无纹理 |
| 64 × 64 | 节点清晰 | 检查小印是否仍可辨认 | 无明显纹理 |
| 32 × 32 / 16 × 16 | 保持识别优先 | 在独立 favicon／功能性图标资源中可省略小印 | 纯色 |

> 对 App Icon 的系统缩放显示，不应简单通过多张路径不同的 PNG 拼凑“品牌一致性”。对 favicon、Toolbar、Menu Bar 等**不同用途的独立资产**，可采用无印章简化符号。

### 10.2 场景清单

**macOS 产品内：**

- Dock / Launchpad：使用完整 App Icon。
- Finder / 应用管理区域：使用完整 App Icon。
- Toolbar：使用单色 Git 分支 Template Symbol，不强塞小篆印章。
- Menu Bar（如将来有对应功能）：优先使用系统风格的单色 Template Symbol。
- About 页面：优先使用完整品牌 Logo 或 App Icon + 品牌信息。

**GitHub：**

- 仓库或组织头像：使用 Symbol Only 或适配尺寸的高对比版本。
- README 横幅：使用完整横向 Logo，辅以适度留白。
- Social Preview：沿用品牌色及标准 Logo；不重复绘制不同的 Git 节点。

**官网与其他材料：**

- 官网 Header：横向 Logo。
- 官网 Favicon：小尺寸独立优化的 Git 主符号。
- 产品介绍图：可包含 App Icon 展示，但不得混淆 App Icon 与横向 Logo 版本。

### 10.3 无障碍与可读性

- 在浅色、深色以及单色背景下分别做图形对比度测试。
- 以三节点 Git 结构的清楚可辨为首要目标；印章字形为次级信息。
- 不依赖仅颜色即可理解产品功能的设计。
- 视觉品牌标志与实际交互按钮的语义标签分开设计，必要时提供辅助功能标签。

## 11. 品牌使用禁则

以下行为禁止出现在正式物料中：

1. **分支不一致：** Logo 三节点与 App Icon 三节点位置或连线不一致。
2. **新增笔画：** 擅自加入向下尾巴、第四个分支或额外端点。
3. **印章错字：** 以普通「庫」字假装小篆，或使用未经核对的 AI 生成笔画。
4. **印章变形：** 改成长方形、椭圆形、圆印，或改成双线方框。
5. **印章重绘：** 不同物料中出现两套「庫」字字形。
6. **内容拥挤：** 内部方印碰到分支、节点或红色主体外缘。
7. **过度装饰：** 叠加太极、山水、祥云、毛笔等其他国风符号。
8. **强纹理：** 印泥噪点过重，降低白色图形可读性。
9. **误用配色：** 随机改为亮红、荧光红、渐变彩虹、金色主标。
10. **图形拉伸：** 独立改变 Symbol、Wordmark 或 Seal 的宽高比例。
11. **不合适的光影：** 横版 Logo 加厚重投影、浮雕、高光、霓虹描边。
12. **位图代源：** 把 AI 海报裁切图当成唯一正式 Logo 文件。

## 13. 制作流程与实施计划

建议将真正的设计交付按以下顺序推进，以避免“先出整张效果图、再反复修正局部”的低效循环。

### 阶段 S1：重建图形母版（最高优先级）

**交付：** `git-symbol.svg`、`icon-master.svg` 初稿。

1. 精确比对已确认的右侧 App Icon 参考形态。
2. 定义三个节点、连线及圆角的固定路径。
3. 去除此前左侧 Logo 多余向下分支。
4. 在 100%、50%、25% 缩放下检查几何形状。
5. 冻结唯一 SVG 路径并记录坐标。

**完成标准：** Logo 与 Icon 可引用同一 Git 母版，路径数据不再有差异。

### 阶段 S2：制作小篆「庫」方印

**交付：** `seal-ku.svg`、`docs/SEAL-SOURCE.md`。

1. 选定并核验「庫」的小篆字形出处。
2. 矢量绘制字形，修正笔画重量与重心。
3. 使用R3的单线近方印框，保留自然圆转与轻微边缘起伏。
4. 制作白色与朱砂红两种等比例换色版本。
5. 测试在主 Logo、256 px、64 px 等场景中的表现。

**完成标准：** 两枚印章结构完全一致；文字正确、线条清楚、比例稳定。

### 阶段 S3：组合正式品牌 Logo

**交付：** 标准横版、深色横版、Symbol、Wordmark。

1. 将最终 Git 母版与内部方印组合。
2. 确定 `WeGit` 衬线字标字体和字距。
3. 在字标右侧加入同源朱砂方印。
4. 冻结元素间距、安全区和横向版式。
5. 做白底、深底、小比例品牌展示测试。

**完成标准：** Logo 与 Icon 中红色主体完全一致，所有组合符合品牌层级。

### 阶段 S4：制作 macOS 系统图标

**交付：** 可编辑图标工程、1024 PNG、系统外观预览。

1. 加入奶白色底座。
2. 将朱砂红主体和极轻微印泥纹理作为可独立调节图层。
3. 导入共享的白色 Git 分支与小篆方印。
4. 检查 Dock、Finder、Launchpad 的显示效果。
5. 检查深色、浅色与系统支持的替代外观。
6. 依目标 Xcode / macOS 版本确定最终导出方式。

**完成标准：** 图标符合目标平台图标规范，缩放后可辨认，没有重复圆角、阴影冲突或印章错位。

### 阶段 S5：衍生 GitHub 与产品物料

**交付：** 头像、Banner、Social Preview、辅助单色图标。

1. 从已定稿 SVG 组合物料。
2. 保持颜色、比例、路径和小篆印章一致。
3. 工具栏／菜单栏单色图标独立进行功能适配。
4. 导出高分辨率位图，不对低分辨率效果图拉伸放大。

**完成标准：** 所有物料可以追溯至主 SVG，没有图形漂移。

### 阶段 S6：验收与发布

**交付：** 完整目录、验收截图、更新后的 `BRAND.md` 和 `CHANGELOG.md`。

- 在真实 macOS 应用和实际 GitHub 页面中验收。
- 检查文件路径、资源引用、透明背景、颜色配置、授权记录。
- 记录正式几何尺寸并将版本升级为“资产定稿版”。

## 16. 定稿总结

WeGit 的 Logo **不是传统文化装饰图案**，而是一个具有东方印记的现代开发工具标识：

- **图形主体：** 简洁、统一、精准的 Git 三节点分支。

- **视觉表达：** 朱砂红与米白、轻微印泥纹理、现代几何和充足留白。
- **产品适配：** 保留原生 macOS 图标质感，同时确保不同场景的识别一致性。

> **最终执行原则：先定 SVG 母版，再组合 Logo 与 App Icon，最后扩展到 GitHub 和其他物料。**
> 不先生成整张视觉海报，再从海报截图或裁切来充当正式品牌文件。

**R4后续：** 将本地素材按实际使用场景接入后，执行真实系统与页面验收；不以资源生成成功代替S6验收。
