## 1. 真实目标与版本边界

让用户更轻松地看懂改动、更准确地选择操作，并在连续工作时感到界面稳定、清晰、响应自然。审美提升来自一致的层级、比例、材质和细节；动效服务于反馈与状态连续性。

保留主窗口「侧栏 → 文件/记录列表 → 内容 → 可选检查器」结构、顶部工具栏和底部提交区。允许调整这些区域内部的分组、对齐、留白、控件样式和信息顺序。设置继续保留六个分类，不更换整套导航。

本版范围是视觉、控件、已有流程的易用性、状态反馈及相关性能修复。Worktree、Cherry-pick/Revert、Blame、选中行暂存和复杂编辑继续按 [v1.2 需求](../docs/V1_2_PLAN.md)推进，不混入本轮。

成功必须同时满足：

1. 用户仍能依靠现有布局和快捷键完成「查看 → 暂存 → 提交 → 同步」。
2. 所有页面使用统一的文字、颜色、间距、图标及控件状态；浅深色与自定义主题均成立。
3. 高频导航、选行和输入即时生效；动画不挡住操作、不改变选择、不拖慢数据呈现。
4. 完成、失败、取消和结果待核对明确区分；危险操作的目标、影响与恢复信息可读。
5. 固定源码的新原生回归、阅读矩阵及有效性能数据满足验收条件。既有性能与交付问题继续跟进。

## 2. 当前基础与重点

### 2.1 已有能力

现有设计系统包含 `AppStyle`、`AppColors`、`GlassControls`、`ThemedForm`、共享搜索框/标题/徽章/反馈组件，以及 17 个自定义主题颜色角色。原生菜单由 `NativeApplicationMenu` 管理。文件与历史选择使用原生 List/Table，暂存复选框与选行已分离。

应用已有动效开关、减少动态效果/透明度及增强对比度分支。欢迎入口 280 ms、悬停 120 ms、状态淡化 160 ms；分段选择使用 `response: 0.28, dampingFraction: 1` 的弹簧。太极 Loading 已确定为完整图形匀速旋转，每圈 2.8 秒；确定进度保留百分比/线性进度。

这些能力应继续完善和验证，不作为「从零新增设计系统」或「补上所有动画」重复建设。

### 2.2 这次观察与证据边界

本轮通过原生 CUA 查看了运行中开发版的更改、分栏 Diff、底部提交区、历史空详情、分支、Stash、标签及设置通用页。运行包路径为 `.build-app/Build/Products/Debug/WeGit.app`；没有核对其全部输入等于源码基线，因此画面用于提出设计方向。浏览完成后恢复原仓库、更改页、选中文件和原提交草稿，关闭本轮打开的设置窗口。

其余页面和状态结合当前源码及已有验收记录纳入计划，尚未完成本轮全页面、全部主题或逐帧审查。开始实施时补齐基线截图与录屏，使用私有夹具；不把个人仓库内容保存到准备提交的设计资料中。

## 3. 视觉方向

目标气质：安静、精确、可信。代码和仓库数据占据视觉中心，主操作清晰，装饰退到背景。

### 3.1 色彩与表面

延续现有表面阶梯：外侧侧栏/检查器略收进，中央文件列表与代码阅读使用连续、稳定的底色。浅色清爽，深色采用当前石墨灰关系；不为增加层次而把每个区域包成卡片。

| 角色 | 规则 |
| --- | --- |
| 蓝色 | 品牌、主操作与焦点；沿用系统强调色及用户自定义主题的控制方式 |
| 中性色 | 普通按钮、工具栏、次级操作、结构线；用明度和间距组织层级 |
| 绿色/红色/提醒色 | 新增/删除/警告等 Git 语义；与符号或文字共同表达，不只靠颜色 |
| Diff 行背景 | 低饱和、低面积干扰；词级高亮和选区叠加后，代码仍可读 |
| 选中态 | 区分活动与非活动窗口、鼠标选择与键盘焦点；保证路径/状态徽章可读 |
| 玻璃材质 | 集中在顶部操作、小型浮层和必要控件；代码、长列表和正文保持稳定底色 |

先改颜色配对和组件用法，再考虑微调默认色值。不推翻已有原生对比度处理，也不全局降低次要文字透明度。

沿用现有 17 个主题字段。新增 hover、pressed、selected、focus、warning 等组件状态色优先由已有语义角色派生；`CustomTheme.validated()` 目前要求字段集合精确一致，直接增加必填颜色键会破坏旧主题导入。若以后确需 schema 变化，另做兼容迁移。

### 3.2 字体、间距与图标

| 项目 | 起始规范 | 验收要点 |
| --- | --- | --- |
| UI 正文 | 系统字体，13 pt；普通内容 regular/medium，分组与页面标题 semibold | 避免每一行、每一项都使用粗体 |
| 元数据 | 11–12 pt；完整值可复制/查看 | 路径、SHA、日期、作者有明确先后，不能因降级颜色而不可读 |
| 代码 | 保留现有等宽字体及 11–24 pt 设置 | 中文、Tab、长行、选区、行号和复制原文一致 |
| 间距 | 4/8/12/16/20/24 pt 的常用刻度；保留现有 14 pt 面板对齐基线 | 同层级对齐，同组更近；局部偏差须有原因 |
| 高度 | 顶部可见表面继续 36 pt；普通控件 30 pt，小控件 24/26 pt | 比较真实可见边缘与命中区域，不能只量 AX 容器 |
| 圆角 | 保留控件 8 pt、表面 14 pt；胶囊用于操作层，少量卡片使用统一圆角 | 不把所有文件图标、计数和元数据都包成胶囊 |
| 密度 | 延续舒适/紧凑两档，分别建立行高和内距规则 | 不通过单纯缩小字体实现紧凑；不得改变用户保存的偏好 |
| 图标 | SF Symbols 为主，统一 size/weight/optical alignment；品牌使用现有几何 | 16/20/24 pt 的实际小尺寸审查，禁用、选中、焦点均清晰 |

在现有 `DesignSystem` 内扩展语义 token 和组件，不另建一套平行样式。建立样册，展示按钮、菜单、搜索、分段控件、徽章、文件行、反馈、确认框在 normal/hover/pressed/focus/selected/disabled/busy/error 状态下的外观。

### 3.3 中国传统视觉语言：纸墨与青瓷

以现代书房作为统一意象：纸墨承载代码和记录，册页整理历史，钤印表达完成，青瓷进入操作层的比例与材质。蓝色 W 保留原形，太极 Loading 保留完整图形、每圈 2.8 秒的既有决定。

| 元素 | 本版落点 |
| --- | --- |
| 纸墨 | 洁净纸白阅读面与墨色文字层级；代码/输入区不铺纸纹 |
| 青瓷 | 普通控件的轻釉色、薄边和温润比例；焦点、选中及正文保持高对比度 |
| 钤印 | 欢迎/侧栏的 W 入印品牌样例；明确提交成功时可用一次 160 ms 的轻落印反馈 |
| 册页/签条 | Tag 与引用徽章、历史详情的轮廓和留白；不动画化翻页或改动真实提交图 |
| 卷藏 | Stash 低频空状态的纸卷/线装册页意象，功能仍称储藏/保存改动 |
| 竹影/山水 | 同风格的欢迎与空状态插画，平时静止，必要时一次局部墨线揭示 |
| 窗棂/榫卯/水纹 | 少量品牌角饰、分段控件的嵌合比例和低频完成反馈，样例成立后择优采用 |

日常界面优先用纸墨、青瓷、签条和印记；插画与角饰集中到低频场景。传统名称用于设计文档，产品动作继续使用易懂的现代词汇。朱色不表达成功；印记不代表签名认证或远端已发布，待核对/取消/失败不落成功印。

此补充继续沿用原生字体、SF Symbols、17 色角色与系统辅助选项。先作为 M0/M1 样册验证，再在 M2/M3 逐页落地；尺寸、配色、动效及验收见 [004](004-traditional-elements.md)。

## 5. 动效规范

### 5.1 按频率和输入方式选择

| 场景 | 本版规则 | 建议参数/边界 |
| --- | --- | --- |
| 文件/历史选行、输入、搜索焦点、快捷键路由 | 即时，内容不随容器飞入或交叉重影 | 不添加人为等待或全区进场 |
| 按钮按下 | 按下即反馈，松开执行；继承原生按钮行为 | 自定义缺口才补 100–160 ms，不能缩放整个工具栏或挪动目标 |
| 悬停 | 小范围背景/颜色反馈 | 现有 ease-out 120 ms，统一为 token |
| 操作状态文字/符号 | 先写入正确状态，再局部淡化 | 现有 feedback 160 ms；文字长度变化不带动整区布局 |
| 分段控件 | 鼠标选择保留短、无回弹的 lens 移动；键盘/AX/程序更新即时 | 保留 spring response 0.28/damping 1；response 不是总时长 |
| 小型内容展开 | 箭头与局部内容有因果关系 | 小内容可用 160–280 ms；大型文件树及代码行即时，不逐行 stagger |
| Popover/Sheet/菜单 | 优先系统呈现与触发点关系 | 不叠加第二套淡入/缩放；自定义浮层仅在实际缺口成立后指定参数 |
| 检查器/主分栏 | 维持原生布局与直接拖动 | 先验证开关/恢复；不为抽屉效果重写 NSSplitView 宿主 |
| 欢迎 | 低频、一次、轻量 | 保留 0.96→1 与 280 ms；不扩展到每次页面切换 |
| Loading | 真忙才出现，确定进度显示数值 | 完整太极 linear/2.8 秒；隐藏、非活动、关闭动效或减少动态效果时停止刷新/使用静态分支 |

动画只观察相关状态，局限在最小必要子树。反复切换从当前显示位置接续，不能先完成旧动画再执行新动作。对于数据更新，结果身份和上下文一致性优先于平滑效果。

默认不采用全页滑入、列表逐项入场、循环渐变、shimmer、庆祝粒子、持续弹跳或动画化代码行。系统/应用减少动效时保留静态反馈与必要颜色/文字变化。

### 5.2 优先修的三项

1. [准确的操作反馈](001-operation-feedback.md)：完成/待核对/失败/取消分开，清除旧成功状态，控制文本与图标的动画范围。
2. [输入来源与动效 token](002-motion-policy.md)：保持鼠标弹簧，键盘及辅助访问即时更新，统一现有曲线与偏好判断。
3. [有效的动效性能验收](003-motion-performance.md)：先解决零帧数据，建立静态/动效开关对照，再决定是否优化 Canvas 旋转实现。

历史加载的连续性属于待录屏确认的改进：同一上下文刷新可保留只读内容与局部忙状态；新查询/文件必须明确切换上下文，旧结果不能冒充新结果。先证明视觉断层，再选择占位或局部更新；不直接增加全区淡入。

## 6. 成熟方案与库的取舍

以下来源在 2026-10-24 查询过。参考其交互原则与能力；采用第三方包之前仍需验证当前工具链、具体版本及实际 macOS 效果。

| 方案 | 适用位置 | 本版建议 |
| --- | --- | --- |
| [Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 与 [Explore SwiftUI animation](https://developer.apple.com/videos/play/wwdc2023/10156/) | 状态、弹簧、Transaction、可中断更新、系统偏好 | 首选。以平台控件及 SwiftUI Animation 为主体 |
| [Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/) | 拖动接续、反向切换、速度连续性 | 使用原生弹簧；工具型点击默认无明显回弹 |
| [Core Animation](https://developer.apple.com/documentation/quartzcore) / AppKit | CALayer 的固定变换、小型原生视图呈现 | SwiftUI 不能满足具体需求时局部使用，先测成本 |
| [Pow](https://github.com/EmergeTools/Pow) | SwiftUI 转场与单次 change effects；Package 声明 macOS 12+ | 可选参考库。仅针对无法简洁实现的局部效果；不把粒子、Shake 或 Jump 当全局风格 |
| [CocoaSprings](https://github.com/MacPaw/CocoaSprings) | 可反复改变目标的 CALayer/NSView/NSWindow 弹簧 | AppKit 高级交互候选，不是本版必需；不照搬其逐帧约束更新到大型分栏 |
| [Lottie](https://github.com/airbnb/lottie-ios) | 设计师交付的矢量动画资产，支持 macOS | 若以后确有复杂低频品牌资产再评估；当前 W/太极不需要新的运行时 |
| [Motion 动效示例](https://motion.dev/docs) | 交互样片、共享元素和参数调试的视觉参考 | 用于学习和原型；原生应用实现仍按 SwiftUI/AppKit 的实际成本与事件体系验证 |

新依赖进入前必须证明：现有原生方案的具体缺口、macOS 实测收益、维护/许可证和离线资源可用性，以及包体、启动、CPU、RSS 的增量。优先封装在一个适配层，并保留降级方式。参考开源库不等于批准安装整套库。

Finder/Xcode 可用于检查原生选择、列表、焦点和工具栏习惯。以下 Git 工具参考有明确用途：

- [Tower 暂存交互](https://www.git-tower.com/help/guides/working-copy/stage-changes/mac)：比较复选框、部分暂存与差异块动作的可理解性；WeGit 现有暂存能力作为基础，本版不引入选中行暂存。
- [Tower Stash](https://www.git-tower.com/help/guides/working-copy/stash/mac)：比较列表/详情和「应用后删除」「恢复暂存状态」的表达，精修现有 Apply/Pop 选择；自动 Stash、快照及局部恢复不在本版范围。
- [Fork](https://git-fork.com/)：比较提交图、Diff、变更列表的阅读层级；其 [Mac 更新记录](https://git-fork.com/releasenotes)也明确关注深色行号、色觉可读性与输入区快捷键，作为检查细节的参考。

以上为官方资料研究，未做这些应用的现场手感对比。实施时记录具体借鉴点，并验证它在 WeGit 中的效果；不宣称复刻另一款产品，不移植未批准的功能。

## 7. 分阶段执行

| 阶段 | 工作与交付物 | 进入下一阶段的条件 | 工程估量 |
| --- | --- | --- | --- |
| M0 基线与样例 | 固定源码/包；全页面和状态截图、关键动效录屏；组件清单；更改/Diff、历史、设置的浅深色目标样例；性能采集自检 | 目标方向明确，当前问题有证据；性能缺口单独登记 | 1–2 日 |
| M1 设计系统 | 字体/间距/状态 token、组件样册；统一按钮/搜索/分段/徽章/反馈 | 样册覆盖两主题、禁用/焦点/忙状态，无重复样式系统 | 2–3 日 |
| M2 核心工作流 | 更改列表、Diff、提交区、历史；正确反馈与旧 notice 清理优先完成 | 私有夹具的正常/失败/取消/快速切换路径通过 | 4–5 日 |
| M3 其余页面 | 分支、储藏、标签、文件历史、Remote/同步、搜索、欢迎/克隆、设置、检查器与菜单面板 | 页面清单无遗漏；命中、键盘、本地化、窄窗成立 | 2–3 日 |
| M4 动效与连续性 | 输入来源策略、token 收敛；条件成立的加载接缝改进；逐帧反向切换检查 | 可中断、正确降级、不延迟数据、不扩大布局动画 | 1–2 日 |
| M5 验收与候选包 | 固定最终源码；阅读/功能/性能矩阵；同环境对照；版本说明和候选包来源 | 新源码门禁及已有交付要求满足后再发布 | 2–3 日 |

单人约 12–18 个工程工作日是初步规模估量，不是发布日期承诺；性能根因修复、托管排队、安装验证和 Beta 反馈的额外周期另计。先完成三类代表页面的视觉样例和组件样册，再扩展所有页面，减少重复返工。

中国传统元素补充另估 2–4 个设计/工程工作日，主要并入样册、品牌和空状态精修；仍以实际素材质量与运行成本决定范围，不新增日历日期承诺。

实现沿用 Issue → 分支 → PR → 必需 CI。共享设计系统先合入，页面批次依赖它；同一文件的 token、状态与视觉修改不要并行覆盖。创建 PR 或生成候选包不代表版本完成。本轮只制定方案，没有新增实现 Issue、安装库或发布制品。

## 8. 验收标准

### 8.1 视觉、阅读与行为

- 全页面清单逐项检查；核心阅读维持现有 144 组合矩阵，新增储藏/标签/Remote/文件历史与设置状态单独补齐，不把新页面混成一个「整体看过」。
- 浅色、深色、自定义主题；舒适/紧凑；980 pt 最小工作区、1292 pt 检查器最小状态、常规与宽窗口；代码字号 11/13/18/24 pt。
- 中文/英文及长分支、长路径、Emoji、换行文件名；完整值可访问和复制。文本不互相覆盖，主操作不被推出窗口。
- 标题/控件/行号基线一致，图标无裁切；可见表面与实际命中均核对。普通文字对比度至少 4.5:1，必要图标/状态边界至少 3:1；在实际玻璃、选区、词级高亮背景上检查。
- ↑↓/←→/Tab/Shift-Tab/Return/Esc 与已有快捷键有效；焦点与选择一致；中文输入法组合输入不中断；搜索清除后可直接继续输入。
- 私有夹具核对暂存、草稿、提交、同步目标、Stash 记录、Tag 对象及 Remote 配置；单纯间距/token 调整不添加逐常量断言，状态与输入行为使用有意义的回归。
- 一般按钮、禁用原因、加载、空结果、错误、取消、冲突和待核对都在清单中。旧成功状态不得覆盖新失败；隐藏说明不等于隐藏必要风险。

### 8.2 动效与性能

沿用普通 Release p95 的既有预算：外壳 500 ms、Status 300 ms、Diff 150 ms、历史首屏 300 ms、稳定外部更新 1000 ms、启动 1000 ms。普通夹具每项至少 30 个有效样本；大型仓库另记录规模、首次读取、RSS、取消与压力条件。

当前 Beta 的实体 Mac 补充采样中 Status/Diff/历史为 386.38/195.32/402.34 ms，仍超预算；这是诊断记录，不能替代托管验证。v1.1.1 应在已固定的新基线定位并修复相关渲染瓶颈，不因美化改版而放宽预算。

新增动效验收目标：

- 同设备、同 Release 源码、同夹具成对比较动效开/关，再比较固定基线/候选；p95 回退超过 5% 必须调查，低于 5% 也不能豁免绝对预算失败。
- 预期滚动/运动的区间要求非零有效帧数与时长，单位及手势区间明确；记录刷新率、帧耗时、卡顿比例、CPU/RSS。有效帧存在时零卡顿可以成立。静止/隐藏/空闲对照允许零重绘，但需有效观察时长、采集器自检及 CPU/RSS，不据此判断 FPS。60 Hz 的 16.7 ms 或 120 Hz 的 8.3 ms 只作每帧设计预算，不把视频导出帧率当实测性能。
- 连续反向切换至少 10 次，内容身份/焦点/选区不跳；动画期间仍可操作；大型树/代码列表不扩大成逐行动画。
- 忙状态只在真实工作时存在；多个可见 Loading、隐藏窗口、非活动场景及减少动效分别测量。空闲不新增持续时钟；循环退出后 CPU/RSS 回到基线波动范围。
- 本地不执行 XCTest。可在执行阶段运行独立检查、编译目标及本机原生观察；实际 XCTest 放在托管流程，先通过实际 1/1 smoke，再运行约定范围。
- 保留不可变源码输入、原始样本、日志、xcresult、截图/录屏和准确计数。缺样本、零帧指标、仅构建成功或 workflow success 不算通过。

### 8.3 交付与使用验证

候选版邀请 3–5 位使用者在私有练习仓库完成：找到并暂存指定文件、提交、定位历史改动、理解 Apply/Pop、核对推送目标。记录完成情况、误点、需要解释的地方与时间；与旧版比较，不凭空设满意度或效率提升百分比。

安装/迁移/回退、受保护 Mac、Beta 反馈、认证兼容性和 Full acceptance 沿用现有质量跟进。旧 Beta `835b8c4` 的 54/54 只覆盖旧输入；包含新 Loading 或本轮样式/状态修改的应用需要自己的证据。v1.0 的一次性发布例外不自动延续。
